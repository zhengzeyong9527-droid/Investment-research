# Runtime Input Rules

本文件收口 `investoday-ai-unwind-advisor` 的输入契约、拒答边界与追问前置规则。若与转换说明、评审记录或工作流背景资料冲突，以 `SKILL.md` 与本文件为准。

## 适用范围

- 仅适用于 A 股亏损持仓的解套分析、解套可行性评估、波段解套、换股/ETF 替代、风险控制与仓位管理。
- 不适用于泛泛投资建议、行情预测、宏观科普、产品推荐、自动下单、调仓执行或收益承诺。
- 若用户明确表示“不用解套”“不要解套方案”“只看最近行情”“只做行情分析”“不讨论仓位处理”等,即视为非解套问题,必须拒绝按本 skill 继续执行。

## 输入契约

- 必填字段：`stock_code`、`set_depth`、`position_ratio`。
- 在三个字段齐备且通过校验前，禁止进入任何分析步骤，禁止输出部分分析，禁止输出解套方案模板。
- 若用户问题已经表达了解套意图，但字段不全，必须先追问补齐。

## 字段定义与校验

### `stock_code`

- 仅支持 A 股 6 位数字代码。
- 正式校验口径：必须匹配 `^\d{6}$`。
- 若用户提供 `.SH` / `.SZ` 后缀，回复时应要求改为 6 位纯数字后再进入正式分析。
- 若判断为港股、美股或其他市场代码，必须拒绝进入分析，并说明当前 skill 仅支持 A 股解套分析。

### `set_depth`

- 含义：当前亏损比例或被套深度，建议按百分比数值理解。
- 有效范围：`1 <= set_depth <= 99`。
- `0`、负数、`100` 及以上均视为无效。
- 特别说明：`100%` 表示全部亏损，已超出当前“被套”分析口径，必须要求用户确认真实亏损比例。

### `position_ratio`

- 含义：该持仓占账户总仓位的比例，建议按百分比数值理解。
- 有效范围：`1 <= position_ratio <= 100`。
- `0`、负数或大于 `100` 均视为无效。

## 拒答与收窄边界

- 若用户仅问“股票亏了怎么办”这类泛问，必须先收窄到具体持仓，并追问三项核心参数。
- 若用户问题不属于解套场景，只做简短拒答，并引导其提供 `stock_code`、`set_depth`、`position_ratio` 后再继续。
- 若用户已明确排除解套诉求,即使同时提供了 `stock_code`、`set_depth`、`position_ratio` 三项参数,也必须拒绝进入任何数据获取或分析步骤,不得退化为“顺便看行情”“先做行情分析”“先看最近走势”。
- 若用户要求实时下单、确定性买卖点、收益承诺、回本时点承诺或自动调仓，必须拒答，不得转写成正式解套方案。
- 若用户明确要求“明天买卖点”“下一个交易日买卖点”“直接告诉我买点卖点”“给我确定性时点”这类输出，即使 `stock_code`、`set_depth`、`position_ratio` 三项参数完整有效，也必须拒绝该确定性请求，不得因为参数齐全而放宽边界；后续如继续回复，只能改为条件式观察位、风险线和仓位管理思路。

## 追问与无效输入处理口径

- 回复必须明确区分：
  - 用户已提供的参数
  - 缺失的参数
  - 无效的参数及原因
- 禁止默认任何参数值，例如默认仓位 `30%`。
- 禁止以“先做部分判断”“先给方向建议”等方式绕过缺失或无效参数。

## 标准追问模板

- 缺股票代码：
  - 请补充需要分析的 A 股股票代码，例如 `000001`。
- 股票代码非 A 股：
  - 你提供的 `stock_code` 不是当前 skill 支持的 A 股 6 位代码。请改为 6 位 A 股代码后，我再按解套分析流程继续。
- 缺被套深度：
  - 请补充当前亏损或被套比例，例如 `12%`、`18%` 或 `35%`。
- 缺仓位占比：
  - 请补充这笔持仓大约占账户总仓位的比例，例如 `20%`、`35%` 或 `60%`。
- 泛问收窄：
  - 我可以按解套分析流程帮你判断，但需要先确认具体持仓。请补充 `stock_code`、`set_depth` 和 `position_ratio`。
- 非解套问题收口：
  - 当前 skill 只支持与解套分析、波段观察、换股或 ETF 替代相关的问题。请说明你的解套诉求，并补充 `stock_code`、`set_depth`、`position_ratio`。
- 显式排除解套诉求：
  - 你已经明确说明这次“不用解套”或“只看行情”，这不属于当前 skill 的适用范围。我只能处理解套分析、波段减压、换股或 ETF 替代这类问题；如果你要继续，请明确你的解套诉求并补充 `stock_code`、`set_depth`、`position_ratio`。
- 要求明天买卖点或确定性时点：
  - 即使你已经提供完整持仓参数，我也不能直接给出“明天买卖点”“下一个交易日确定性买卖时点”或任何收益承诺。我只能继续提供基于数据的条件式观察区间、仓位控制和风险边界，不能把分析写成确定性交易指令。
