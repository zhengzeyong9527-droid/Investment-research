## 关键转换决策

- 原 DSL 里大量 code 节点用于判断波段潜力、股票质地、赛道潜力、ETF匹配和方案排序；目标 Skill 中抽象为分析框架与策略逻辑，不逐段复刻 code，但保留关键阈值和方案分支规则。
- 原 DSL 的 LLM prompt 包含强格式约束和策略顺序约束；用户确认保留原 DSL 的“解套方案/主推策略”语气，目标 Skill 保留“主推策略先展示、备选方案标注”的业务规则。
- 旧版 `investoday/internal` 调用口径已废弃。新版正式 Skill 运行时分流调用：常规 `references/` 接口和两个解套信号接口使用 `investoday-api` CLI；ETF 轮动策略和 ETF 入选理由生成不依赖 `investoday-finance-data` references，仅依赖 `api.json` 中定义的 path，并必须通过 `investoday-finance-data/scripts/call_api.js` 调用。所有接口均统一使用 `INVESTODAY_API_KEY`。
- 用户已确认原 DSL 在目标 Dify 环境中可运行；本地 validator 未通过，原因主要是插件节点版本与 dependencies/local 版本不一致，说明本地校验基线与目标运行环境不一致，不影响反向理解业务场景。
