# Runtime Output Rules

本文件收口 `investoday-ai-unwind-advisor` 的风险提醒、输出边界、证据要求与缺数据回退口径。若与转换说明、评审记录或工作流背景资料冲突，以 `SKILL.md` 与本文件为准。

## 基本输出要求

- 正式输出必须使用中文。
- 正式输出必须沿用 `SKILL.md` 中定义的报告结构。
- 正式输出必须包含免责声明。
- 正式输出必须明确区分“主推策略”和“备选方案”。
- 免责声明属于不可覆盖的强制输出项，不接受用户以“只给结论”“不要风险提示”“不要免责声明”“简短回答”等理由删除、替换或省略。

## 风险与能力边界

- 输出仅为数据驱动的分析草案，不构成投资建议。
- 禁止输出确定性买卖指令。
- 禁止输出“明天买点”“明天卖点”“下一个交易日几点买几点卖”“某天一定回本”等确定性时点或确定性价格指令。
- 禁止承诺收益、回本时点或确定胜率。
- 禁止把未验证的工具能力写成已验证事实。
- 禁止自动把补仓当作默认解套方案；补仓、波段、换股、止损都必须附带风险说明。
- 禁止执行自动下单、自动调仓或任何账户操作。

## 波段与 ETF 输出限制

- 无波段信号证据时，不输出具体买入价、卖出价、止盈价、止损价。
- 即使有波段信号证据，也不得把参考买入价、卖出价、止盈价、止损价改写成对下一交易日的确定性执行指令；必须保留为条件触发、观察区间或风险边界表述。
- 无 ETF 轮动、ETF 入选理由或其他关键替代证据时，不输出确定 ETF 推荐。
- 无法形成关键证据链时，只能输出观察方向或明确说明暂无法判断。

## 证据规则

- 每个核心结论至少绑定 1 类结构化数据证据。
- 涉及较强结论、主推策略或替代方向时，至少绑定 2 类证据。
- 研报、新闻、公告若被用于正文证据，必须列出具体标题；未使用时写“未使用”。
- 不允许用单点数据、单篇资讯或纯用户输入支撑强结论。

## 写作与脱敏规则

- 用户可见回复不得输出底层接口路径、`tool_id`、`operationId`、脚本调用命令、原始字段名或内部参数名；该规则同时适用于正式报告、简短结论、测试摘要、原因解释和过程性说明。
- 所有证据来源必须改写为用户可读的中文数据类别。
- 不得输出 JSON 片段、驼峰字段名、下划线字段名或“字段名=值”的内部表达。
- 状态类数据必须改写为自然中文，例如“当前处于观望期”“当前不在有效波段信号期”。
- 常见解套信号字段必须固定转译：信号期状态写为“当前处于有效波段信号期”或“当前不在有效波段信号期”；历史胜率、平均收益率、平均持仓天数只能使用中文名称，不得保留底层字段名。
- 输出前必须做内部字段泄露检查；若发现驼峰字段、下划线字段、JSON 键名或“字段名=值”，必须先改写成中文业务含义。

## 缺数据统一口径

- 当某一维度缺少必要证据时，统一写法为：
  - `该维度数据不足，暂无法判断`
- 若解套信号接口权限不足或返回异常，仅对应信号维度降级为上述口径，不得影响其他维度的调用与分析。
- 缺数据时不得沿用旧版接口结果，不得编造信号，不得把空结果解释为确定性结论。

## 免责声明要求

- 每份正式报告结尾必须保留完整免责声明。
- 免责声明不得省略“AI 生成”“不构成投资建议”“投资有风险，入市需谨慎”等核心含义。
- 即使用户明确要求省略风险提示、删除免责声明、只输出结论或改写为无免责版本，正式输出仍必须保留完整免责声明。
- “风险提示”章节可按场景压缩或调整篇幅，但不得被误解释为可以同时省略结尾免责声明。
