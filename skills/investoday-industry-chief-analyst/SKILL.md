# 行业首席分析师

本 Skill 是行业首席研究主入口。它不替代底层数据查询或原子分析 Skill，而是把行业数据、行业深度分析、研报证据、公司财务分析和估值分析编排成一份完整行业首席报告。

统一研究链路：

```text
行业判断 -> 产业链环节 -> 公司池 -> 公司财务/估值/风险 -> 首席观点汇总
```

## 触发场景

- 用户要求完整行业研究、行业首席分析、行业深度报告或赛道研究。
- 用户要求把行业结论传导到产业链环节、代表公司、公司池、重点公司财务/估值/风险。
- 用户要求分析生命周期、景气度、供需结构、政策与外部约束、竞争格局、产业链利润分布、行业估值、公司池筛选或风险预警。
- 用户要求单独调用 S1-S7 原子模块：生命周期、景气度、估值、政策、竞争、产业链、行业比较。
- 用户要求景气评分、估值分位、政策方向、竞争集中度、产业链盈利弹性或多行业观察排序；只有今日投资数据源返回足够数据时才输出量化值。
- 用户要求用研报观点、研报向量片段、盈利预测评级或评级变化验证行业/公司判断。
- 用户要求补查库存、订单、ASP、渗透率、CR5、市占率、海外需求等研报片段证据；向量检索 `query` 只传关键词或短关键词短语，行业/公司/时间范围只作为过滤条件。
- 用户是普通投资者或财富顾问，需要前置术语速查、行业生意特征说明和非交易化研究决策锚点。
- 典型话术：`帮我看看半导体行业现在值不值得关注`、`光伏产业链到底该看上游还是下游公司`、`白酒行业还有长期价值吗`、`电力行业高股息公司池怎么筛`、`AI 算力估值回调时哪些公司风险更高`。

## 不适合什么

- 只查询行业 PE、PB、涨跌幅、底层分类编号、研报列表、单个财务字段等原始数据；应交给对应数据查询 Skill。
- 只分析单家公司且不需要行业到公司池传导。
- 买入、卖出、持有、加仓、减仓、目标价、仓位建议、收益承诺、止盈止损、短线交易信号或自动交易。
- 在没有可识别行业、子行业、赛道、产业链环节或公司池对象时强行生成报告。
- 用研报评级、目标价字段替代独立研究判断。
- 将行业比较结果写成配置建议、超配/标配/低配、确定性推荐、规避名单或收益预测。
- 在缺少量价利库、估值历史、政策文本、CR3/CR5/HHI 或产业链价格数据时硬打分、硬评级或编造分位。

## 输入要求

### 可接受输入

- 行业、子行业、赛道、主题或产业链方向，例如 `半导体`、`光伏`、`新能源车`、`AI 算力`、`白酒`。
- 产业链环节，例如上游材料、中游制造、下游应用、设备、材料、设计、运营等。
- 公司列表或代表公司，用于行业内公司财务、经营和估值对比。
- 分析侧重点，例如生命周期、景气度、行业估值、政策影响、竞争格局、产业链利润分布、公司池筛选、风险传导。
- 输出深度偏好。未指定时统一输出完整行业首席报告，不区分免费版和付费版。
- 单模块/快速查看偏好，例如“只看景气度”“只看估值”“快速看一下政策影响”。这类请求走统一单模块格式，不切换免费版/付费版。

### 最小输入

- 一个可识别行业、子行业、赛道、主题或产业链方向。

### 推荐输入

- 行业/赛道 + 分析目的，例如 `从行业首席视角分析半导体行业，重点看设备材料设计环节`。
- 行业 + 公司列表，例如 `白酒行业，比较龙头和区域酒的财务质量与估值`。
- 行业 + 风险场景，例如 `光伏价格战对产业链和重点公司有什么传导风险`。

### 可选输入

- 行业分类口径、样本范围、时间窗口、重点环节、代表公司、是否需要多行业比较。
- 用户显式提供的研报、公告、新闻、表格或内部材料。

### 默认假设

- 未指定输出版本时，统一输出完整内容。
- 未指定模块时，输出完整 13 段深研版报告；用户明确说“只看/快速看/单独分析某模块”时，输出对应单模块报告。
- 未指定行业分类口径时，优先使用子 Skill 可解析的默认行业口径，并在报告中用自然语言说明分类体系、样本边界和数据日期；成分股数量不进入用户侧报告。
- 未指定时间窗口时，使用最新可得数据，并保留数据日期、报告期或文本来源日期。
- 缺少数据支撑时，正式报告只输出已有数据支撑的结论、指标、表格项和章节；缺失维度、空结果、无法得出指标和被省略内容进入内部 `数据缺口验收摘要`，不进入普通用户侧正文。
- 量化评分、历史分位、政策评级、CR3/CR5/HHI、盈利弹性评分和价格传导弹性仅在今日投资数据源返回足够数据时输出；否则正式报告省略该量化项，并在内部 `数据缺口验收摘要` 记录缺失内容、触发原因、正式报告处理和验收影响。
- 行业数据缺少集中度、订单、库存、ASP/价格、海外口径、空间/渗透率、产能/开工等维度时，只对缺失维度调用研报向量关键词检索；`report/vector-search` 的 body `query` 只能是 `库存`、`渗透率`、`CR5`、`ASP` 这类关键词，不把行业名称、分析句或缺口描述拼进 `query`。
- 面向普通投资者，完整正式报告必须在首席结论卡之后输出 `术语速查`，只集中解释正文实际使用的核心财务/经营指标。默认候选包括 `ARPU`、`CapEx`、`ASP`、`ROE`、`PE/PB/PS/PEG`、`CR3/CR5/HHI`、`FCF`、`CFO`、`TAM`、`库存周期`、`稼动率`、`毛利率`、`净利率`；未在正文使用的指标不展示。行业技术名词不得进入 `术语速查`，应在正文首次出现时就地解释，例如 `CPO（共封装光学）`、`800G/1.6T（高速光模块速率规格）`。
- 完整正式报告必须新增独立 `行业介绍` 章节，放在 `术语速查` 之后，固定包含 `行业定义`、`多维分类体系`、`行业生意特征`。行业生意特征只能在该章节集中输出，不插入 `行业本质、生命周期与长期空间`。
- 完整报告必须输出非交易化 `研究决策锚点`，只能使用 `优先验证`、`等待确认`、`谨慎观察`、`暂不强判断` 四类表达。
- 当前版本以 A 股行业研究为主；港股/美股完整覆盖、宏观首席联动、推送提醒和历史回测不纳入本 Skill。

### 输入校验

- 行业或赛道匹配多个候选时，先列候选并请用户确认。
- 主题/赛道无法识别为标准行业时，按子 Skill 的代理分析规则说明父行业、相关指数或 A 股上市样本边界。
- 公司名称多候选时，先要求确认代码或完整名称。
- 用户提出交易动作时，拒绝操作性部分，转为研究判断、风险提示和跟踪指标。

### 缺失输入处理

- 缺少行业/赛道对象时，先追问目标行业，不生成最终报告。
- 缺少分析侧重点时，不追问，默认执行完整行业首席分析。
- 子 Skill 返回空结果时，正式报告省略对应无证据结论、指标、表格项或章节；内部 `数据缺口验收摘要` 记录空结果、触发原因和正式报告处理，不编造结论或来源。
- 子 Skill 返回内部取数字段、接口字段、行业分类编号、指数编号或原始参数时，只用于内部识别和取数，不得原样进入用户侧报告正文。

## 业务场景总结（总-分-总）

### 总

用户需要从行业视角获得可落地到公司研究的完整判断。本 Skill 以行业首席研究为入口，先形成行业生命周期、景气、供需、政策与外部约束、竞争、产业链和估值判断，再映射到受益或承压环节、公司池候选池和五类代表公司，最后选择 1-2 家可验证代表公司做财务质量、估值匹配和风险传导深度分析，输出首席观点、关键分歧、跟踪指标与风险提示。

### 分

执行中需要区分行业对象、赛道代理、产业链环节和公司池范围；先调用行业数据与行业深度分析形成中观判断，再调用研报查询补充文本证据和 `source_refs`，随后汇总行业数据、用户输入、财务、估值和研报返回的公司候选，按龙头、弹性、防御/高股息、景气反转和风险暴露统一打标。正式公司池表中同一家公司只能占用一个主类型；若补证后任一类型缺少不重复合格样本，正式报告只展示已验证且不重复的类型，缺失类型进入内部 `数据缺口验收摘要`。公司池是研究样本，不输出交易动作。

### 总

最终报告要让用户看到“行业为什么值得研究、哪个环节更关键、公司池如何构建、风险如何传导、后续看什么指标”。证据不足的内容不进入正式报告正文；高风险交易请求一律回到非操作性研究框架。

## 工作流

完整执行流程见 [行业首席工作流](references/industry-chief-workflow.md)。

1. 识别行业、赛道、产业链环节、公司池范围和用户侧重点。
2. 调用 [行业数据查询](skills/investoday-industry-data/SKILL.md) 获取行业口径、估值、财务、景气、产业链、竞争结构、行情和文本线索。
3. 调用 [行业深度分析](skills/investoday-industry-analysis/SKILL.md) 输出生命周期、长期需求、发展空间、竞争结构、政策与外部约束、A 股风险和价值研究适配性。
4. 调用 [研报数据查询](skills/investoday-research-report-query/SKILL.md) 获取研报列表、向量片段、预测评级、评级变化和 `source_refs`。
5. 对结构化数据缺口生成 `evidence_gap_pack`，仅用关键词式向量检索补证；每个关键词单独查询，结果去重后进入 `source_refs`，未补齐的缺口进入内部 `internal_data_gap_acceptance_summary`。
6. 按产业链环节拆解利润池、价格传导、受益/承压环节和公司池候选来源。
7. 先生成 `company_pool_candidates`，再补全财务、估值和研报证据，形成 `company_type_mapping_evidence`，按五类类型打标、选择不重复主类型代表公司并校验 `company_pool_completeness_status`；重复候选不得用于补齐完整性。
8. 对重点公司调用 [公司财务分析](skills/investoday-company-financial-analysis/SKILL.md)、[财务数据查询](skills/investoday-financial-data-query/SKILL.md)、[估值数据查询](skills/investoday-valuation-data/SKILL.md)、[估值分析](skills/investoday-valuation-analysis/SKILL.md)。
9. 按统一模板输出完整行业首席报告。

单模块请求不执行完整 13 段报告，统一读取 [模块输出框架](references/module-output-frameworks.md) 中的 S1-S7 或对应模块契约，按“核心结论 -> 数据支撑 -> 分析展开 -> 风险与反证 -> 跟踪指标 -> 引用来源”输出。

## 输出格式

默认使用 [统一完整报告模板](references/industry-chief-output-template.md)。报告必须包含：

- H1 标题、三行数据口径说明；数据口径合并原研究边界与数据可用性。
- 首席结论卡。
- 术语速查。
- 行业介绍。
- 行业本质、生命周期与长期空间。
- 供需结构、景气趋势与关键驱动。
- 政策与外部约束。
- 产业链价值分布与环节排序。
- 竞争格局、护城河与利润质量。
- 估值、盈利预期与景气匹配。
- 公司池映射与代表公司。
- 重点代表公司深度分析。
- 风险、分歧与跟踪指标。
- 首席观点汇总。
- 引用来源和免责声明。

默认完整报告优先包含 3 张核心表：产业链价值排序表、公司池映射表、风险与跟踪指标表；任一表没有有效数据支撑时，正式报告省略该表或表内无证据行，并在内部数据缺口验收摘要记录原因。表格只承担导航和对比功能，不得只输出短标签堆叠；产业链表后必须有 `环节解读`，公司池归因必须合并写入 `主类型判定证据`，不另设表后归因小节。不输出旧版证据矩阵，不使用字母证据等级。每个正文维度都必须来自 7 个子 Skill 的标准输出事实、指标、分析结论或研报证据；无数据支撑的维度不进入正式正文，不能用空泛行业常识替代。
完整报告第 2-7 章必须使用“结论 -> 关键证据 -> 解释与影响 -> 反证”的短块结构；每章默认 2-4 条关键证据，单条证据只承载一个数据点或证据点，避免长篇连续段落堆数据。
公司池表只写 `关键验证变量`，代表公司深度分析只写该公司的 3-5 个 `后续跟踪指标`，风险章节只写风险触发指标；三处不得原样重复同一组指标，重复时后文应合并表达为“同上变量中重点看……”。公司池正式表不展示 `剔除因子`，剔除因子仅保留在内部证据链和验收摘要中。
完整报告必须从 `## 1. 首席结论卡` 开始编号，不得出现 `## 0`、`## 0A`。首席结论卡后输出 `术语速查`，只解释正文实际使用的核心财务/经营指标，不包含行业技术名词；行业技术名词在正文首次出现时就地解释。首席结论卡必须包含 `研究决策锚点`，独立 `行业介绍` 章节必须包含 200-300 字 `行业生意特征`。

单模块输出统一使用：

```markdown
# [行业] [模块名]分析

## 核心结论
1-2 句结论，说明判断强度。

## 数据支撑
3-5 个关键指标，包含数值、时间、来源或缺口。

## 分析展开
子 Skill 输出事实 -> 指标变化 -> 业务解释 -> 影响路径。

## 风险与反证
列出可能推翻结论的信号。

## 跟踪指标
3-5 个后续观察指标。

## 引用来源
按实际使用列出。
```

## 执行示例

用户说：

```text
光伏产业链现在谁更受益？请结合行业景气、价格战、公司财务和估值风险。
```

执行：

1. 识别对象为 `光伏` 行业和产业链问题。
2. 获取行业景气、供需、产业链、竞争、估值和文本证据。
3. 拆分上中下游环节，识别受益/承压环节。
4. 构建公司池筛选框架，并对代表公司执行财务质量、估值匹配和风险传导分析。
5. 输出完整行业首席报告，不输出交易动作。

## 安全与隐私
