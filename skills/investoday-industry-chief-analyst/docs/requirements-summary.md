# 需求表映射摘要

来源：

- `首席skill需求.xlsx`：共 23 项需求模块。
- `行业首席Skill需求.pdf`：补充 S1-S7 原子模块、量化方法论、测试用例和合规要求；详细追踪见 `references/pdf-requirements-traceability.md`。

## 总体要求

- 主 Skill：行业首席分析师。
- 统一输出完整内容，不区分免费版和付费版。
- 总链路：行业判断 -> 产业链环节 -> 公司池候选池 -> 五类实名代表公司 -> 公司财务/估值/风险 -> 首席观点汇总。
- 依赖 Skill：行业深度分析、行业数据查询、公司财务分析、财务数据查询、估值分析、估值数据查询、研报数据查询。
- 不包含其他综合诊断 Skill。
- 输出边界：不输出买卖指令、目标价、仓位、收益承诺、止盈止损或自动交易动作。
- 用户侧口径：内部取数字段、分类编号、指数编号、endpoint、接口字段、子 Skill 名、`Investoday` 和原始参数只用于取数，不进入正式报告正文。
- 成分股数量不进入用户侧报告。
- 完整报告不输出旧版证据矩阵，不使用字母证据等级。
- 默认完整报告表格：产业链价值排序表、公司池映射表、风险与跟踪指标表。
- 完整报告公司池只展示龙头型、弹性型、防御/高股息型、景气反转型、风险暴露型中已验证、证据充足且不重复的实名代表公司；缺少任一类型时正式报告省略该类型，内部摘要记录缺口，并至少分析 1-2 家已验证代表公司。
- S1-S7 单模块可单独调用：生命周期、景气度、估值、政策、竞争、产业链、行业比较统一使用单模块输出格式。
- 景气评分、估值分位、政策评级、CR3/CR5/HHI、产业链盈利弹性等量化项有数据才输出；无数据、空结果或无法得出时正式报告省略，内部摘要记录。
- PDF 中的配置建议、超配/低配、最优投资层位、推荐顺序统一改写为研究观察优先级、验证环节和风险提示。
- 当前版本以 A 股行业研究为主；港股/美股完整覆盖、宏观首席联动、推送提醒、历史回测和外部图谱库不纳入。

## 统一输出要求

- 报告必须包含 H1、三行数据口径说明、首席结论卡、分述章节、代表公司分析、综合/首席观点、引用来源和免责声明。
- 默认完整报告包含产业链价值排序表、公司池映射表、风险与跟踪指标表。
- 产业链价值排序表后必须输出 `环节解读`；公司池归因写入 `主类型判定证据`，不另设表后归因小节；正式公司池表不展示 `剔除因子`。
- 首席结论卡后输出 `术语速查`；可选量化摘要仅展示有数据支撑的生命周期阶段、景气评分、估值分位、政策方向、竞争格局和验证环节。
- 单模块报告统一包含核心结论、数据支撑、分析展开、风险与反证、跟踪指标、引用来源。
- 关键结论必须绑定数据或来源。
- 研报证据必须携带 `source_refs`。
- 数据缺失时正式报告省略对应内容，不允许补造；缺口进入内部 `数据缺口验收摘要`。
- 公司池正式表只展示可验证、证据充足且不重复的实名代表公司；任一类型缺失时内部记录，不输出交易名单。
- 报告正文不得暴露 `Investoday`、子 Skill 名、内部取数字段、分类编号、指数编号、endpoint、接口字段或原始参数。
- 报告正文不得展示成分股数量。
- 每个维度必须从子 Skill 输出事实、指标、分析结论或研报证据展开，不写空泛摘要。
- 完整报告和单模块报告都必须包含时效与历史规律局限说明。

## 验收重点

- `module-output-frameworks.md` 是否覆盖全部 23 项。
- `industry-chief-output-template.md` 是否能承载全部模块。
- `industry-chief-output-template.md` 是否使用三行数据口径、12 段结构、代表公司分析和 3 张核心表。
- `source-skill-contracts.md` 是否只列 7 个指定子 Skill。
- 用户侧报告是否隐藏内部口径字段。
- 用户侧报告是否隐藏成分股数量。
- 完整报告公司池是否不重复、证据充足，并包含 1-2 家已验证代表公司深度分析；风险暴露型是否有多因子证据。
- 高风险交易请求是否被拒绝并转为非操作性研究。
- S1-S7 单模块是否能独立输出且格式统一。
- PDF 需求追踪矩阵是否覆盖 S1-S7、P0/P1/P2、测试和合规要求。
- 量化数据缺失时是否不编造评分、分位、评级、CR3/CR5/HHI 或盈利弹性。
