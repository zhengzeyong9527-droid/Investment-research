## 分支逻辑

| 分支 | 条件 | 处理方式 | 输出要求 | 不适用边界 |
|---|---|---|---|---|
| 完整行业首席分析 | 行业对象明确，未限定单模块 | 执行全流程 | 使用数据驱动深研版完整报告模板 | 不输出交易动作、成分股数量和内部口径字段 |
| 单模块分析 | 用户只问某一模块 | 读取对应模块框架 | 模块结论 + 必要边界 + 风险；缺口进内部验收摘要 | 不强行展开完整报告 |
| 公司池映射 | 用户问行业如何落到公司 | 先行业结论，再生成候选池、五类打标和完整性校验，再验证代表公司 | 公司池映射表、完整性状态或代表样本分析 | 不输出“买入名单” |
| 重点公司联动 | 用户提供公司列表 | 调用财务和估值分析 | 同行对比、财务质量、估值匹配、风险传导 | 不给目标价和仓位 |
| 研报证据补充 | 用户要研报/片段/评级 | 调用研报查询 | 证据摘要和 `source_refs`，正式报告使用的研报必须包含发布时间、发布机构和研报标题 | 不选择性拼接证据，不输出半截研报来源 |
| 用户指定专项表 | 用户明确要同行对比表、公司列表、单模块表格或筛选表 | 在主报告或模块报告后追加扩展表 | 标注“用户指定扩展表” | 不把扩展表变成默认模板 |
| S1-S7 单模块 | 用户明确只问生命周期、景气度、估值、政策、竞争、产业链或行业比较 | 使用统一单模块格式 | 核心结论、数据支撑、分析展开、风险反证、跟踪指标、引用来源 | 不输出完整 13 段报告 |
| 缺口关键词补证 | 结构化数据缺少集中度、订单、库存、ASP、海外口径、空间/渗透率、产能/开工 | 按 `evidence_gap_pack` 逐关键词调用向量检索 | 只把命中片段作为弱文本证据；无命中记录内部验收摘要 | 不用长 query，不用研报片段替代结构化数据 |
| 核心模块无数据 | 任一核心模块无数据 | 正式报告省略无证据章节、指标或表格项 | 内部验收摘要记录缺失内容、触发原因、正式报告处理和验收影响 | 不使用模型记忆补数 |
| 量化不可算 | 缺少量价利库、估值历史、政策文本、CR3/CR5/HHI、产业链价格或毛利率 | 不输出分数、评级、弹性或分位 | 内部验收摘要记录缺失字段和正式报告省略动作 | 不硬打分、不用研报观点替代结构化数值 |
| 高风险交易 | 交易化请求 | 拒绝操作性部分 | 可继续提供非操作性研究 | 不提供买卖动作 |
| 公司池候选不足 | 补证后任一公司类型无不重复合格实名代表公司 | 正式表只展示已验证且不重复的公司类型 | 内部验收摘要记录缺失类型、缺失证据和候选池缺口 | 不用重复公司、公司类型、概念词或行业环节替代公司名称 |

## 研究决策锚点规则

| 锚点 | 使用条件 | 用户侧表达边界 |
|---|---|---|
| 优先验证 | 结构化数据或研报证据指向改善，但仍需订单、库存、毛利率、现金流等继续确认 | 表达为优先跟踪和验证，不写买入或配置 |
| 等待确认 | 结论方向不弱，但关键验证指标尚未在正式报告中充分支撑 | 表达为等待关键指标确认，不写错过机会 |
| 谨慎观察 | 估值、政策、竞争、财务或现金流风险较突出 | 表达为风险约束更强，不写卖出或规避名单 |
| 暂不强判断 | 结构化数据和研报证据不足、冲突或无法识别同口径 | 表达为暂不形成强研究结论，不写确定性判断 |

## 内容深度规则

- 每个章节必须按“子 Skill 输出事实 -> 指标变化 -> 业务解释 -> 对行业/环节/公司的影响 -> 风险或反证”组织。
- 不能只写行业定义、通用常识或浓缩摘要。
- 结构化数据优先于研报文本；研报观点只作为补充证据。
- 子 Skill 无有效数据时，正式报告省略无证据内容，内部验收摘要记录缺口和无法判断的维度。
- 代表公司分析必须覆盖行业位置、财务质量、估值匹配、景气传导、风险暴露和跟踪指标。
- 完整报告第 2-7 章必须使用短块结构：`结论`、`关键证据`、`解释与影响`、`反证`。关键证据默认 2-4 条，每条只放一个数据点或证据点。
- 对用户样例中类似“通信行业的本质...”这类长段输出，必须拆成短块，避免把行业本质、财务数据、长期空间和反证揉成一整段。
- 产业链价值排序表和公司池映射表不得只输出短标签；产业链表后必须用短段解释价值兑现路径，公司池归因必须写入 `主类型判定证据`，不再额外输出表后归因小节。
- 公司池正式表不展示 `剔除因子`，剔除因子只作为内部字段用于记录为什么未分到其他类型或为什么省略候选。
- 公司池表、代表公司深度分析和风险表不得原样重复同一组指标；重复时后文合并表达，不机械复写。
- 代表公司深度分析不得只罗列财务和估值指标；每条关键证据必须说明数据含义、验证了哪项公司质量，以及行业景气如何传导到收入、毛利率、现金流或估值容错率。
- 第 3 章必须新增独立 `行业介绍`，包含 `行业定义`、`多维分类体系`、`行业生意特征`；行业生意特征控制在 200-300 字，通信行业需区分运营商/通信服务与通信设备两类商业逻辑。
- `术语速查` 的解释必须短、贴近投资者理解，例如 `ARPU：单用户平均收入`、`ASP：平均销售价格`、`FCF：自由现金流`；仅解释正文实际使用的核心财务/经营指标。正文出现的行业技术名词必须在首次出现时就地解释，不进入 `术语速查`。

## 评分与排序规则

- 综合评价矩阵必须公开评分维度和依据。
- 没有足够数据的维度不得打满分或硬打分。
- 排名只代表研究观察顺序，不代表买卖建议。
- 行业轮动信号只输出观察信号和风险条件，不输出切换仓位建议。
- 景气评分只在量/价/利润/库存或对应行业代理指标足够时输出；缺少关键维度时正式报告省略评分。
- 政策方向五级评级只在有政策、公告、研报或新闻来源时输出；无文本证据不评级。
- CR3/CR5/HHI 只能来自直接披露或同口径公司级数据；否则正式报告省略该指标，可保留有证据支撑的样本观察。
- 产业链盈利弹性评分和价格传导弹性必须有价格、毛利率、供需或研报证据支持；否则只输出定性传导路径。
- 行业比较的排序名称统一为“研究观察优先级”，不得写“推荐排名”“规避清单”“配置建议”。

## 公司池类型打标规则

- 龙头型：收入、净利润、ROE、研发、现金流或研报龙头地位中至少两项支持。
- 弹性型：收入/利润高增、利润率改善、经营杠杆、订单/产品周期或研报景气证据中至少两项支持。
- 防御/高股息型：经营现金流、分红/股息率、估值稳健、低波动业务或负债稳健中至少两项支持。
- 景气反转型：历史承压 + 最新改善同时成立，改善证据可来自利润增速、毛利率、现金流、订单、库存或研报反转线索。
- 风险暴露型：至少两个风险因子成立，且其中至少一个来自财务或估值数据；风险表达只写研究风险，不写卖出、规避或黑名单。
- 同一家公司只能进入一个主类型；主类型优先级为防御/高股息型、龙头型、弹性型、景气反转型、风险暴露型，未采用的交叉属性写入主类型判定证据、主要风险或内部剔除因子。
- 完整公司池五类要求真实且不重复代表公司；重复候选不得补齐完整性，缺失类型进入内部验收摘要。

## 兜底策略

| 场景 | 兜底 |
|---|---|
| 行业不可识别 | 追问行业、赛道或代表公司 |
| 主题只能代理分析 | 正式报告只说明父行业和相关代理边界；数据缺口进入内部验收摘要，不展示内部编号 |
| 研报无结果 | 正式报告不写研报空态；内部验收摘要记录空结果和查询口径 |
| 缺口补证无向量结果 | 正式报告不写无结果缺口；内部验收摘要记录，不编造集中度、库存、订单或 ASP |
| 公司财务数据缺失 | 不做财务质量强判断 |
| 估值分位缺失 | 不输出估值高低强结论 |
| 子 Skill 返回内部编号 | 改写为自然语言分类和样本边界，不展示编号 |
| 子 Skill 返回成分股数量 | 仅内部使用，不进入报告正文 |
| 无代表公司样本 | 正式公司池表省略缺失类型；内部验收摘要列出缺失类型和缺失证据 |
| 用户要求交易动作 | 拒绝并转为风险提示和观察指标 |
| 用户要求超配/低配/配置比例 | 拒绝配置化表达，改为行业比较、观察优先级和风险条件 |
| 用户要求港股/美股完整覆盖 | 说明当前以 A 股行业研究为主；仅使用现有子 Skill 返回的可得数据 |
| 用户要求宏观联动、推送或回测 | 说明当前不纳入，改为列可观察宏观/行业指标或回归测试建议 |
