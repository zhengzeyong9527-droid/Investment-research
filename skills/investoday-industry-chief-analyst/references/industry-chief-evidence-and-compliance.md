# 证据与合规规则

## 证据使用原则

用户侧报告不展示字母证据等级。内部判断只按以下优先顺序使用证据：

1. 可追溯结构化数据、公司公告、年报、监管文件、行业协会或权威机构原始披露。
2. 今日投资返回的行业/公司财务、估值、行情、景气、预测和同口径样本分析。
3. 研报观点、新闻、公告摘要、向量片段和文本线索。
4. 用户提供资料，必须标注“用户提供资料”。

结构化数据优先于研报文本；研报观点只能作为补充证据或分歧来源，不能替代财务、估值、行情和行业数据。

## 核心要求

- 每条首席判断优先绑定至少 2 个今日投资数据源输出事实或分析结论；如只能取得 1 个证据点，必须降低措辞强度。
- 景气评分、估值历史分位、政策方向评级、CR3/CR5/HHI、产业链盈利弹性和价格传导弹性必须绑定可追溯数据、报告期和来源；缺关键字段时不得输出具体分数或评级。
- 文本类结论至少包含来源类型、标题、发布方/机构、日期和支持的判断。
- 研报列表、研报舆情、研报向量片段和预测评级样本只要进入正式正文或引用来源，必须同时具备发布时间、发布机构和研报标题；缺少任一项时，不得在正式报告中写成“研报片段：日期，主题，机构”或“研报舆情：日期，标题”，应省略该来源并写入内部 `数据缺口验收摘要`。
- 研报评级、目标价字段只作为研报样本展示，不转化为买卖建议、上涨空间或收益承诺。
- 没有数据时正式报告省略对应指标、表格行或章节；缺失内容进入内部 `数据缺口验收摘要`，不得在正式正文写缺口话术。
- 不得引用未获取的数据、新闻、研报、公告、政策或主观传闻。
- 不得把代理样本、父级行业或文本线索写成全行业真实事实。
- 每个章节都必须按“子 Skill 输出事实 -> 指标变化 -> 业务解释 -> 对行业/环节/公司的影响 -> 风险或反证”展开。
- 研报向量检索用于补证时，body `query` 只能传关键词或短关键词短语；命中片段只能作为文本证据或弱补充，不得替代同口径结构化集中度、订单、库存、ASP、海外口径或渗透率数据。
- 正式报告前部用 `术语速查` 集中解释正文实际使用的核心财务/经营指标；不得包含 CPO、NPO、LPO、800G/1.6T、MPO、5G-A、6G 等行业技术名词。行业技术名词必须在正文首次出现时就地解释；术语解释只用于提升普通投资者可读性，不能代替数据、来源或判断依据。
- 研究决策锚点只能表达研究验证动作，不能转换为买卖、仓位、目标价、配置比例、收益或规避指令。
- 第 3 章 `行业介绍` 必须包含行业定义、多维分类体系和行业生意特征；行业生意特征解释商业逻辑、收入变量、利润变量和验证指标，不能用空泛行业定义替代。
- 使用历史分位、历史政策复盘、历史价格传导或景气拐点规律时，必须说明历史规律不代表未来结果。
- 完整报告和单模块报告都必须说明报告反映生成时点数据状态；超过三个月建议基于最新数据重新分析。

## 用户侧口径脱敏

- 内部取数字段、接口字段、行业分类编号、指数编号、endpoint、原始参数和调试信息只能用于取数、路由和子 Skill 交接，不得出现在用户侧正式报告正文。
- 子 Skill 返回内部分类字段、行业分类编号、指数编号或接口原始字段时，主 Skill 必须只吸收其业务含义，并改写为客户可读表达。
- 报告正文不得展示成分股数量或成分股总数。
- 引用来源和报告头部 `数据口径` 只展示自然语言分类体系、数据日期、报告期和代理口径。
- 如用户明确要求底层编号或接口字段，先说明正式报告不展示该类内部字段；确需排查数据口径时，只能在单独的技术说明中列出，并不得混入投研正文。

## 表格使用约束

- 完整报告默认包含 3 张核心表：产业链价值排序表、公司池映射表、风险与跟踪指标表。
- 不输出旧版证据矩阵。
- 不展示字母证据等级。
- 公司池映射表必须先生成候选池并完成五类实名代表公司校验；龙头、弹性、防御/高股息、景气反转、风险暴露每类至少 1 家真实代表公司。
- 风险暴露型也必须实名，至少绑定两个可追溯风险因子，且其中至少一个来自财务或估值数据；不得用公司类型、行业环节、概念词或单一高估值因素替代公司名称。
- 公司池映射表只展示已验证、证据充足且不重复的代表公司；同一家公司只能占一个主类型。
- 完整公司池任一类型无法取得不重复合格代表公司时，正式报告省略该类型；缺失类型、重复候选和证据缺口进入内部 `数据缺口验收摘要`。
- 完整报告至少选择 1-2 家可验证代表公司做深度分析；若仅有有限样本，只对已验证且不重复公司展开，不在正式正文说明公司池缺口。
- 用户明确要求同行对比表、公司列表、单模块表格或专项筛选表时，可以追加“用户指定扩展表”。
- S1-S7 单模块请求按统一单模块格式输出；可追加该模块专项表，但不复制完整报告全部表格。

## 引用来源格式

报告末尾按实际使用来源列示：

```markdown
## 引用来源

- 数据来源今日投资数据市场。
- 研报：<发布时间>，<发布机构>，《<标题>》
- 新闻：<发布时间>，<标题>，<发布机构>
- 公告：<发布时间>，<标题>
```

未使用新闻、研报或公告时，不保留占位符。

研报引用校验：

- 正式引用来源中的每条研报必须含有发布时间、发布机构和研报标题三要素。
- 正文中使用“某机构《某研报》（某日期）指出/显示/认为……”这类写法，避免只写“研报片段显示”。
- `source_refs` 中缺少标题、机构或日期的研报片段只能作为内部溯源缺口，不进入普通用户正式报告。

## 合规边界

禁止输出：

- 买入、卖出、持有、加仓、减仓、建仓、清仓。
- 目标价、仓位建议、收益承诺、止盈止损、短线买卖点。
- 自动下单、交易执行、组合调仓。
- 配置建议、超配、标配、低配、确定性推荐、规避名单。
- “一定上涨”“安全收益”“稳赚”“确定低估”等确定性投资承诺。

允许输出：

- 行业研究判断。
- 研究决策锚点：优先验证、等待确认、谨慎观察、暂不强判断。
- 产业链受益/承压环节。
- 公司池筛选逻辑、代表样本和后续分析入口。
- 代表公司财务质量、估值匹配、风险暴露、跟踪指标。
- 非操作性表达，例如“当前证据更支持……”“仍需观察……”“该风险可能通过……路径传导”。
- 行业比较中的“研究观察优先级”“待验证方向”“风险条件”。

## 风险表达

- 风险提示只揭示风险，不转化为交易动作。
- 风险必须说明触发条件和证据。
- 无法验证的风险不进入正式报告风险表；如需验收追踪，写入内部 `数据缺口验收摘要`。
- 交易结构风险需要与基本面风险分开表达。
- 行业比较和轮动只揭示研究观察优先级、触发条件和风险，不转化为配置建议。
- 产业链“最优投资层位”统一改写为“更值得验证的环节”，并说明验证指标和反证。

## 输出自检

交付前检查：

- 是否包含三行数据口径、引用来源和免责声明。
- 是否保留未使用来源占位符。
- 是否出现买卖、目标价、仓位或收益承诺。
- 是否出现配置建议、超配、标配、低配、确定性推荐或规避名单。
- 是否将研报评级/目标价转化为投资建议。
- 是否在量化数据缺失时硬输出评分、分位、评级、CR3/CR5/HHI 或盈利弹性。
- 是否在首席结论卡后输出 `术语速查`，且没有用解释替代证据。
- `术语速查` 是否只覆盖正文实际出现的核心财务/经营指标，且未混入行业技术名词。
- 是否输出了研究决策锚点，并保持非交易化表达。
- 是否在第 3 章 `行业介绍` 写出行业定义、多维分类体系和 200-300 字行业生意特征。
- 是否包含三个月时效和历史规律局限说明。
- 是否把代理样本写成全行业事实。
- 是否在正式报告中省略缺失数据，并在内部 `数据缺口验收摘要` 中追踪。
- 是否把研报向量检索的长问题拆成关键词，并避免把研报片段写成硬结构化事实。
- 是否每条正式研报引用都包含发布时间、发布机构和研报标题，且正文没有“研报片段：日期，主题，机构”这类半截来源。
- 是否暴露 `Investoday`、子 Skill 名、成分股数量、内部取数字段、行业分类编号、指数编号、endpoint、接口字段或原始参数。
- 是否误输出旧版证据矩阵或字母证据等级。
- 是否包含产业链价值排序表、公司池映射表、风险与跟踪指标表。
- 是否包含 1-2 家已验证且不重复代表公司深度分析；若公司池五类未补齐，是否省略缺失类型并在内部摘要追踪。
