# 行业首席工作流

本文件定义 `investoday-industry-chief-analyst` 的完整编排流程。主 Skill 不直接读取底层接口响应，只读取 7 个子 Skill 的标准输出字段。

## 总流程

```text
行业对象识别
-> 行业数据查询
-> 行业深度分析
-> 研报证据补充
-> 缺口关键词补证
-> 产业链价值排序
-> 公司池候选池
-> 五类公司类型打标
-> 代表公司筛选
-> 代表公司财务分析
-> 代表公司估值匹配
-> 风险传导
-> 内部数据缺口验收摘要
-> 首席观点汇总
```

## Step 0：行业对象识别

目标：确认用户要分析的对象是标准行业、子行业、主题赛道、产业链环节，还是多行业比较。

输入：

- 行业名称、子行业、主题、赛道或子 Skill 可识别的内部取数字段。
- 可选：产业链环节、代表公司、公司列表、分析重点。

处理：

- 标准行业：进入完整行业首席流程。
- 主题/赛道：先尝试映射到父行业、相关指数或 A 股上市公司样本，并在报告中说明代理边界。
- 多行业：进入行业比较、综合评价矩阵或轮动信号流程。
- 单模块：用户明确说只看生命周期、景气度、估值、政策、竞争、产业链或行业比较时，进入 S1-S7 单模块流程，使用统一单模块输出格式。
- 对象不明确：进入 `clarify_target`，先追问。

输出：

| 字段 | 类型 | 说明 |
|---|---|---|
| `analysis_target` | 文本 | 行业/赛道/主题名称 |
| `analysis_scope` | 文本 | 行业口径、代理边界；用户侧不展示内部编号或覆盖数量 |
| `route` | 枚举 | 完整分析、单模块、多行业、公司池、研报证据 |
| `missing_inputs` | 清单 | 必要但缺失的信息 |

## Step 1：行业数据查询

调用：[行业数据查询](../skills/investoday-industry-data/SKILL.md)

目标：取得行业口径、估值、财务、盈利、景气、预测、行情、产业链、竞争结构、市场空间、政策线索和代表公司候选。

标准输出：

- 自然语言行业口径和代理边界。
- 行情估值、行业估值、财务报告期和机构预测样本日期。
- 行业估值、财务、盈利、景气、行情和预测核心指标。
- 产业链、竞争结构、市场空间、政策与外部约束、行业标签线索。
- 代表公司候选或公司样本线索；成分股数量不进入用户侧报告。
- 数据缺口、代理口径和样本估算说明；缺口仅进入内部验收摘要，不进入普通用户正式报告。

量化可用性检查：

- 景气评分：检查量/价/利润/库存或行业代理指标是否足够；关键维度缺失时正式报告省略评分，内部验收摘要记录无法得出原因。
- 估值分位：检查 3年/5年/10年历史估值是否返回；缺期限时正式报告只保留可得期限，内部验收摘要记录缺失期限。
- 政策方向：检查政策、公告、新闻或研报文本证据；无文本时不评级。
- 竞争集中度：检查 CR3/CR5/HHI 是否直接披露或有同口径公司级数据；不足时只输出样本观察。
- 产业链盈利弹性：检查价格、毛利率、供需或研报证据；不足时不硬算评分。

缺口维度识别：

| 缺口维度 | 触发条件 | 候选关键词包 |
|---|---|---|
| 集中度 | 未取得细分环节 CR3/CR5/HHI、真实市场份额或市占率 | `CR3`、`CR5`、`HHI`、`市场份额`、`市占率` |
| 订单 | 未取得订单、新签订单或在手订单数据 | `订单`、`在手订单`、`新签订单`、`订单能见度` |
| 库存 | 未取得库存、渠道库存或去库存进度 | `库存`、`库销比`、`去库存`、`渠道库存` |
| ASP/价格 | 未取得 ASP、均价或产品价格序列 | `ASP`、`均价`、`价格`、`产品价格` |
| 海外口径 | 未取得海外收入、海外需求、出口或全球销售数据 | `海外收入`、`海外需求`、`出口`、`全球销售` |
| 空间/渗透率 | 未取得渗透率、市场空间或 TAM 证据 | `渗透率`、`市场空间`、`TAM` |
| 产能/开工 | 未取得产能、产能利用率或开工率 | `产能`、`产能利用率`、`开工率` |

每个缺口维度最多选择 3-4 个关键词。关键词只用于研报向量检索 body `query`；行业、公司、时间范围、topK 和分类口径只作为过滤条件。

## Step 2：行业深度分析

调用：[行业深度分析](../skills/investoday-industry-analysis/SKILL.md)

目标：形成行业定义、分类体系、行业生意特征、生命周期、周期属性、长期需求稳定性、发展空间、竞争结构、政策与外部约束、A 股风险和价值研究适配性判断。

标准输出：

- 生命周期标签：导入、成长、成熟、衰退、反转。
- 行业定义、多维分类体系和行业生意特征：用于完整报告第 3 章 `行业介绍`。
- 行业本质、景气和长期空间判断；正式报告的 `行业本质、生命周期与长期空间` 章节不得重复输出行业生意特征。
- 竞争结构、政策与外部约束、A 股特色风险。
- 适配类型、前提、反证和观察指标。

## Step 3：研报证据补充

调用：[研报数据查询](../skills/investoday-research-report-query/SKILL.md)

目标：补充行业/公司研报证据、观点、向量片段、盈利预测评级、评级变化、机构预测样本说明和 `source_refs`。

原则：

- 研报片段只作为文本证据，不能替代结构化财务、估值或公告事实。
- 研报评级、目标价字段只展示样本和口径，不转化为投资建议。
- 空结果只说明当前口径下无结果，不推导无风险或无机会。
- 研报列表、研报舆情、研报向量片段和预测评级样本进入正式报告前，必须先生成并校验 `source_refs`：发布时间、发布机构、研报标题、证据类型和用途齐全。缺少标题、机构或日期任一项时，该研报片段不进入正式正文或引用来源，缺口进入内部验收摘要。
- 正式正文引用研报时使用“<发布机构>《<研报标题>》（<发布时间>）指出/显示/认为……”的客户可读写法，禁止只写“研报片段显示”或“研报舆情显示”。

## Step 3A：缺口补证与关键词向量检索

目标：对行业数据和行业深度分析未覆盖的关键维度做有限补证，提高库存、订单、ASP、渗透率、集中度、海外口径等文本证据命中率。

处理：

1. 汇总 Step 1 和 Step 2 的 `data_gaps`，形成内部字段 `evidence_gap_pack`。
2. 仅对缺失维度发起研报向量检索；已有结构化数据的维度不重复扩展。
3. 每个缺口维度从关键词包中选 3-4 个以内关键词，每个关键词单独调用一次 `report/vector-search`。
4. `report/vector-search` 的 body `query` 只能是单个关键词或短关键词短语，例如 `库存`、`渗透率`、`CR5`、`ASP`；不得传入 `通信行业库存和订单怎么看`、`请查通信行业CR5和市场份额证据` 这类长句。
5. 行业代码、公司代码、机构、日期范围、分类、topK 作为过滤条件传入，不拼入 `query`。
6. 命中的研报片段去重后进入 `source_refs`，并标注用于哪个缺口维度。
7. 研报片段只能作为文本证据或弱补充，不能替代结构化数据；未取得同口径证据时，不写入普通用户正式报告，只记录到内部 `internal_data_gap_acceptance_summary`。

输出内部字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `evidence_gap_pack` | 结构化对象 | 缺口维度、触发原因、已选关键词、过滤范围、查询状态 |
| `vector_keyword_queries` | 清单 | 实际发起的关键词式向量检索；每条只包含一个 `query` 关键词和过滤条件摘要 |
| `source_refs` | 去重清单 | 命中的发布时间、发布机构、研报标题、证据类型、用途；缺标题/机构/日期任一项的命中仅内部记录，不进入正式引用来源 |
| `internal_data_gap_acceptance_summary` | 结构化清单 | 缺口模块、缺失内容、触发原因、正式报告处理和验收影响；仅用于测试、质检、验收或调试 |

## Step 3B：S1-S7 单模块分流

触发条件：用户明确只问某个原子模块，或用“快速看一下/只看/单独分析”限定输出范围。

单模块范围：

| 模块 | 输出重点 |
|---|---|
| S1 生命周期 | 阶段、置信度、长期空间、反证和观察指标 |
| S2 景气度 | 量价利库、景气评分、拐点信号、跟踪指标 |
| S3 估值 | PE/PB/PS/PEG、3年/5年/10年分位、盈利匹配 |
| S4 政策 | 五级政策方向、时间线、受益/承压环节、持续性 |
| S5 竞争 | CR3/CR5/HHI、护城河、格局趋势、利润质量 |
| S6 产业链 | 环节排序、盈利弹性、价格传导、风险 |
| S7 行业比较 | 多行业观察矩阵、研究观察优先级、风险条件 |

输出格式：读取 `module-output-frameworks.md` 的“单模块统一输出格式”。单模块不输出完整 12 段报告；如果量化数据缺失，正式输出省略量化项，内部验收摘要记录缺口，不硬打分。

## Step 4：产业链价值排序

目标：把行业判断拆到真实产业链环节，并排序其价值、景气和利润兑现。

默认输出：

### 产业链全景表

| 环节 | 核心组成部分 | 代表企业/技术 |
|---|---|---|

### 重点细分领域发展

按 2-4 个有证据支撑的重点细分领域，说明技术突破、国产替代、需求变化或商业模式变化，以及对产业链环节的传导。

### 产业链价值排序表

| 环节 | 景气/兑现判断 | 价值来源 | 关键证据 | 主要风险 |
|---|---|---|---|---|

处理：

- 优先使用行业产业链数据和研报直接披露。
- 按行业真实环节拆分，不强套上中下游。
- 不能确认利润池时，正式报告省略利润池强结论或无证据表格行，内部验收摘要记录缺口，不写成全行业事实。
- 明确重资产/轻资产、扩产周期、折旧压力、存货、应收和回款压力。
- 表格只承担导航和对比功能，不得只输出“技术、客户、规模、风险”等短标签；价值来源和关键证据必须用完整短语说明。
- 表后必须输出 `环节解读`：对每个展示环节各写 80-120 个中文字符，解释为什么该环节重要、利润如何兑现、最该验证什么。

## Step 5：公司池映射

目标：从行业结论映射到公司池候选池、公司类型、实名代表公司和后续分析入口。

完整链路：

```text
候选生成 -> 财务估值补全 -> 类型打标 -> 代表公司选择 -> 完整性校验 -> 输出
```

### 5A. 候选生成

- 汇总 `company_pool_candidates`：来源只能是行业数据代表公司候选、用户输入、财务数据查询、公司财务分析、估值数据查询、估值分析或研报查询标准输出。
- 每个候选必须保留公司名、可识别公司对象、来源 Skill、数据日期、候选环节、候选指标、研报来源、财务摘要、估值摘要、风险因子和内部数据缺口。
- 行业财务排名、产业链产品收入/利润样本、行业行情样本只能作为候选线索；没有财务或估值补全前，不得直接进入最终代表公司表。

### 5B. 财务估值补全

- 对候选公司补取财务质量、现金流、负债、分红或回购、估值水位、历史分位、成长匹配和估值风险。
- 结构化数据优先；研报只用于解释业务地位、订单、产品周期、政策或海外风险等文本证据。

### 5C. 类型打标

- 龙头型：收入、净利润、ROE、研发、现金流或研报龙头地位中至少两项支持。
- 弹性型：收入/利润高增、利润率改善、经营杠杆、订单/产品周期或研报景气证据中至少两项支持。
- 防御/高股息型：经营现金流、分红/股息率、估值稳健、低波动业务或负债稳健中至少两项支持。
- 景气反转型：历史承压 + 最新改善同时成立，改善证据可来自利润增速、毛利率、现金流、订单、库存或研报反转线索。
- 风险暴露型：至少两个可追溯风险因子成立，且其中至少一个来自财务或估值数据；不得只凭“涨得多”或“估值高”点名公司。
- 主类型选择：同一家公司同时满足多个类型时，只能进入一个主类型；按防御/高股息型、龙头型、弹性型、景气反转型、风险暴露型的顺序优先分配，未采用的交叉属性写入主类型判定证据、主要风险或内部剔除因子。

### 5D. 代表公司选择与完整性校验

- 完整公司池必须覆盖龙头型、弹性型、防御/高股息型、景气反转型、风险暴露型五类，每类至少 1 家、默认 1-2 家实名代表公司，且公司名不得重复。
- 候选不足时不得用同一家公司重复补齐多个类型；正式公司池表只展示已验证且不重复的主类型，缺失类型进入内部验收摘要。
- 生成 `company_type_mapping_evidence`，逐类型记录入选证据、剔除因子、风险因子和内部数据缺口。
- 生成 `company_pool_completeness_status`：内部枚举只使用 `complete` 或 `incomplete`；五类均有不重复合格实名代表公司时为 `complete`，任一类型缺失或只能靠重复公司补齐时为 `incomplete`。
- 若补证后任一类型仍缺少不重复合格代表公司，正式报告不使用公司类型、行业环节或概念词替代代表公司；缺失类型和缺失证据写入内部 `internal_data_gap_acceptance_summary`。

默认输出：

| 公司类型 | 代表公司/样本 | 对应环节 | 主类型判定证据 | 关键验证变量 | 主要风险 |
|---|---|---|---|---|---|

处理：

- 公司样本必须来自行业数据、用户输入、财务数据查询、公司财务分析、估值数据查询、估值分析或研报查询标准输出。
- 不能凭模型记忆、主题热度或常识编造公司。
- `主类型判定证据` 必须写清为什么归入该类型，至少包含类型门槛对应的 2 项证据或风险因子，并说明行业结论如何传导到该公司；不得只堆指标数值。
- 正式公司池表不展示 `剔除因子`；剔除因子保留在内部 `company_type_mapping_evidence` 和内部验收摘要中。
- 公司池表后不输出独立归因小节；行业传导、归类理由和未采用的交叉属性合并写入 `主类型判定证据` 或 `主要风险`。
- 公司池表只写 `关键验证变量`；代表公司深度分析只写公司级 `后续跟踪指标`；风险章节只写风险触发指标，三处不得原样重复同一组指标。
- 完整公司池五类都必须有不重复实名代表公司；风险暴露型也必须点名真实公司，但表达为风险样本，不写成规避名单。
- 若任一类型无不重复合格代表公司，正式公司池表只输出已验证类型，内部验收摘要记录缺失类型、触发原因和正式报告处理。
- 公司池是代表样本和研究分层，不是推荐名单。

## Step 6：代表公司财务分析

调用：

- [财务数据查询](../skills/investoday-financial-data-query/SKILL.md)
- [公司财务分析](../skills/investoday-company-financial-analysis/SKILL.md)

目标：从公司池中至少选择 1-2 家可验证代表公司，验证公司池逻辑是否被财务质量支持。

必看维度：

- 业务与行业位置。
- 收入、利润、ROE、毛利率、净利率、经营现金流、自由现金流、资产负债压力。
- 研发投入、资本开支、存货/应收、分红或回购。
- 关键证据与解读：每条公司数据必须说明其业务含义，例如利润率是否验证议价能力、经营现金流是否验证利润兑现、负债和自由现金流是否放大周期风险。
- 景气传导：说明行业变量如何落到该公司收入、毛利率、现金流或估值容错率，不得只复述公司池表里的关键验证变量。
- 财务质量风险；缺失财务字段进入内部验收摘要。

## Step 7：代表公司估值匹配

调用：

- [估值数据查询](../skills/investoday-valuation-data/SKILL.md)
- [估值分析](../skills/investoday-valuation-analysis/SKILL.md)

目标：判断代表公司估值是否与行业景气、公司财务质量、成长持续性、现金流和行业地位匹配。

必看维度：

- PE、PB、PS、PEG、历史分位、行业相对位置。
- 成长匹配、现金流匹配、股息/回购辅助。
- 估值风险、盈利预测上修/下修；缺失估值字段进入内部验收摘要。

## Step 8：风险传导

目标：把行业风险传导到环节、公司类型和代表公司。

默认输出：

| 风险 | 触发信号 | 影响环节/代表公司类型 | 跟踪指标 |
|---|---|---|---|

风险类型包括基本面、政策、估值、竞争、产业链、财务、交易结构和事件风险。

## Step 9：首席观点汇总

目标：把前述模块收束为可阅读的首席判断。

必含：

- 行业判断：当前行业状态和判断强度。
- 环节判断：更值得验证和更承压的环节。
- 公司判断：代表公司样本的财务/估值验证结论。
- 最大分歧：最可能改变判断的变量。
- 跟踪框架：未来优先观察的行业、环节、公司层指标。
- 研究决策锚点：在 `优先验证`、`等待确认`、`谨慎观察`、`暂不强判断` 中选择一类，并解释对应的研究验证动作。
- 下一步验证顺序：先看行业变量，再看产业链环节，最后看代表公司财务/估值。
- 合规边界：只输出研究结论，不输出交易动作。
- 时效与历史规律局限：报告反映生成时点可得数据状态；超过三个月建议基于最新数据重新分析，历史规律不代表未来。

## Step 9A：内部数据缺口验收摘要

目标：把正式报告中被省略的缺失数据、空结果、无法得出的指标、缺失公司类型和被省略表格项单独沉淀，用于测试、质检、验收或调试。

输出字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `gap_module` | 文本 | 缺口所属模块，如估值、公司池、研报证据、政策 |
| `missing_content` | 文本 | 缺失指标、字段、样本、章节或表格项 |
| `trigger_reason` | 文本 | 空结果、字段缺失、候选不足、无法得出或重复公司无法补齐 |
| `formal_report_handling` | 文本 | 正式报告省略指标、省略表格行、省略章节或仅保留已验证样本 |
| `acceptance_impact` | 枚举 | `通过`、`需关注`、`阻断` |

规则：

- 本摘要不进入普通用户正式报告。
- 内部验收模式、测试模式、质量评估或开发调试场景必须输出本摘要。
- 正式报告静态检查禁止出现取数失败、空结果或无法得出等缺口用语；这些内容只能出现在本摘要。

## 内容深度约束

- 每个章节都必须按“子 Skill 输出事实 -> 指标变化 -> 业务解释 -> 对行业/环节/公司的影响 -> 风险或反证”展开。
- 不得只写空泛行业定义或常识摘要。
- 无数据时正式报告省略对应内容，不得用模型记忆补数；缺口进入内部数据缺口验收摘要。
- 报告头部必须使用三行数据口径说明，成分股数量不进入用户侧报告。
- 不输出旧版证据矩阵，不使用字母证据等级。
- 量化评分、分位、评级、集中度和盈利弹性有数据才输出；缺少依据时正式报告省略，内部验收摘要记录。
- 完整报告必须从 `## 1. 首席结论卡` 开始编号，不得出现 `## 0` 或 `## 0A`。
- 完整报告必须在首席结论卡后输出 `术语速查`，后文不重复堆解释；术语解释只覆盖正文实际出现的核心财务/经营指标，不包含行业技术名词。行业技术名词在正文首次出现时就地解释。
- 第 3 章必须输出独立 `行业介绍`，包含 `行业定义`、`多维分类体系`、`行业生意特征`；行业生意特征 200-300 字，通信行业需区分运营商/通信服务与通信设备。
- PDF 中的“配置建议、超配/低配、最优投资层位、推荐顺序”统一改写为“研究观察优先级、验证环节、风险条件”。
