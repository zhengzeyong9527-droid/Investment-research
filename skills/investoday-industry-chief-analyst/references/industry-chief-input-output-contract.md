# 行业首席输入输出契约

## 输入契约

| 输入项 | 类型 | 是否必填 | 来源 | 校验规则 | 缺失处理 |
|---|---|---|---|---|---|
| 行业/赛道对象 | string | 是 | 用户输入 | 可被行业数据或行业深度 Skill 识别 | 追问目标行业/赛道 |
| 分析范围 | enum/list | 否 | 用户输入 | 生命周期、景气、估值、政策、竞争、产业链、公司池等 | 默认完整行业首席分析 |
| 产业链环节 | string/list | 否 | 用户输入或行业数据 | 可映射为真实产业链环节 | 不限制环节，完整展开 |
| 公司列表 | list | 否 | 用户输入或行业数据 | 公司名称/代码可识别 | 用作代表公司候选；无法识别时追问 |
| 代表公司 | string/list | 否 | 用户输入、行业数据或公司池输出 | 公司对象唯一且可取财务/估值数据 | 多候选时追问；无可验证样本时列入内部候选缺口 |
| 多行业列表 | list | 条件必填 | 用户输入 | 至少 2 个行业 | 缺少时转完整单行业分析 |
| 用户资料 | file/text | 否 | 用户提供 | 必须明确来源 | 标注为用户提供资料 |
| 输出要求 | string | 否 | 用户输入 | 不得要求交易动作 | 默认完整 Markdown 报告 |
| 单模块/快速偏好 | string/enum | 否 | 用户输入 | 生命周期、景气度、估值、政策、竞争、产业链、行业比较之一 | 进入统一单模块输出格式 |
| 市场范围 | enum/list | 否 | 用户输入/子 Skill 支持 | 当前以 A 股为主；港股/美股仅在子 Skill 返回可用数据时使用 | 无数据时正式报告不展示对应市场，内部摘要记录 |

## 输出契约

| 输出项 | 类型 | 是否必出 | 来源/生成方式 | 空值处理 | 说明 |
|---|---|---|---|---|---|
| 报告标题 | Markdown H1 | 是 | 行业对象 + 模板 | 无行业对象则不生成 | `[行业/赛道]行业首席研究报告` |
| 报告头部三行口径 | 引用行 | 是 | 当前日期 + 子 Skill 日期口径 | 日期缺失则写“最新可得” | 分析日期、数据口径、说明；数据口径合并原研究边界与数据可用性 |
| 首席结论卡 | 清单 | 是 | 全流程汇总 | 无数据支撑的判断不输出 | 当前判断、研究决策锚点、关键变量、验证环节、代表公司方向、最大分歧、改变判断信号；有数据时可写量化摘要 |
| 可选量化摘要 | 清单/短句 | 否 | 行业数据、行业深度、估值、研报 | 缺失、空结果或不可算则不输出 | 生命周期阶段、景气评分、估值分位、政策方向、竞争格局、验证环节 |
| 术语速查 | 表格/清单 | 条件必出 | 输出生成规则 | 正文无财务/经营指标则不输出 | 首席结论卡后集中解释正文实际使用的核心财务/经营指标，不包含行业技术名词，后文不重复堆解释 |
| 行业介绍 | 文本 + 表格 | 条件必出 | 行业深度、行业数据、研报查询、主流程解释 | 证据不足则省略无证据内容 | 行业定义、多维分类体系、行业生意特征；行业生意特征集中说明怎么赚钱、收入/利润变量和验证指标 |
| 行业本质、生命周期与长期空间 | 短块结构 | 条件必出 | 行业深度、行业数据、研报查询 | 证据不足则省略无证据内容 | 结论、关键证据、解释与影响、反证；只写生命周期和长期空间，不输出行业生意特征 |
| 供需结构、景气趋势与关键驱动 | 短块结构 | 条件必出 | 行业数据、行业深度、研报查询 | 高频数据缺失则省略对应指标 | 结论、关键证据、解释与影响、反证；需求、供给、价格、利润、景气、关键变量 |
| 政策与外部约束 | 短块结构 | 条件必出 | 行业深度、行业数据、研报查询 | 无政策证据则省略政策评级或时间线 | 结论、关键证据、解释与影响、反证；国内政策、监管约束、海外约束、卡点环节、影响路径 |
| 产业链价值分布与环节排序 | 短块结构 + 表格 + 环节解读 | 条件必出 | 行业数据、行业深度、研报查询 | 利润池不足时省略盈利弹性项 | 固定包含产业链全景表、重点细分领域发展、产业链价值排序表和环节解读 |
| 竞争格局、护城河与利润质量 | 短块结构 | 条件必出 | 行业深度、行业数据、研报查询 | 无集中度披露则省略 CR3/CR5/HHI | 结论、关键证据、解释与影响、反证；集中度、竞争方式、护城河、利润质量、潜在颠覆 |
| 估值、盈利预期与景气匹配 | 短块结构 | 条件必出 | 估值数据、估值分析、行业数据、研报查询 | 分位缺失则省略分位判断 | 结论、关键证据、解释与影响、反证；PE/PB/PS/PEG、历史分位、盈利预期、周期位置、风险溢价 |
| 公司池映射表 | 表格 | 条件必出 | 行业数据、用户输入、财务、估值和研报子 Skill | 只展示已验证、证据充足且不重复的公司类型 | 实名代表公司、对应环节、主类型判定证据、关键验证变量、主要风险；正式表不展示剔除因子，归因写入主类型判定证据 |
| 重点代表公司深度分析 | 分公司段落 | 条件必出 | 公司财务、财务数据、估值数据、估值分析、行业深度、研报查询 | 只分析已验证且不重复代表公司；无验证公司则不输出 | 完整报告优先分析 1-2 家可验证代表公司；关键证据必须解释数据含义和行业传导 |
| 风险与跟踪指标表 | 表格 | 条件必出 | 全流程汇总、研报查询、估值分析 | 缺证据风险不进入正式表 | 风险、触发信号、影响环节/代表公司类型、跟踪指标 |
| 首席观点汇总 | 文本/清单 | 是 | 主 Skill 汇总 | 缺证据时降低强度 | 行业、环节、公司、分歧、跟踪、合规边界 |
| 单模块报告 | Markdown 报告 | 条件必出 | `module-output-frameworks.md` | 缺关键数据则省略无证据量化项 | 用户只看 S1-S7 任一模块时输出核心结论、数据支撑、分析展开、风险反证、跟踪指标、引用来源 |
| 引用来源 | 无序清单 | 是 | 实际使用来源 | 不编造来源 | 今日投资、研报/新闻/公告；正式使用的研报必须同时包含发布时间、发布机构和研报标题 |
| 免责声明 | 固定文本 | 是 | 固定文案 | 不允许省略 | 合规边界 |
| 时效与历史规律声明 | 文本 | 是 | 固定规则 + 数据日期 | 不允许省略 | 报告反映生成时点数据，超过三个月建议基于最新数据重新分析；历史规律不代表未来 |
| 内部数据缺口验收摘要 | 表格/结构化清单 | 条件必出 | 全流程缺口汇总 | 无缺口则不输出 | 仅测试、质检、验收或调试场景单独输出，不并入普通用户正式报告 |

## 字段口径

下表为主 Skill 内部交接契约，字段名不得原样展示在用户侧报告正文。用户侧只展示自然语言口径、数据日期、报告期和代理边界，成分股数量不进入用户侧报告。

|---|---|---|---|---|---|---|---|
| `industry_name` | 行业/赛道名称 | string | 是 | 用户输入/行业数据 | 查询时点 | 无法执行分析 | 半导体 |
| `analysis_scope` | 研究范围 | string | 是 | 主流程生成 | 查询时点 | 口径未确认 | 今日投资行业分类/主题代理 |

| `research_decision_anchor` | 研究决策锚点 | enum | 是 | 主流程生成 | 查询时点 | 证据不足时为暂不强判断 | 优先验证/等待确认/谨慎观察/暂不强判断 |
| `business_model_summary` | 行业生意特征 | text | 是 | 行业深度/行业数据/主流程解释 | 查询时点 | 行业逻辑证据不足时降级说明 | 200-300 字商业逻辑说明，仅输出在行业介绍章节 |
| `term_explanations_used` | 已解释财务/经营指标清单 | list | 否 | 输出生成规则 | 查询时点 | 无财务/经营指标 | ARPU、CapEx、ASP、ROE、CFO |
| `lifecycle_stage` | 生命周期阶段 | enum | 是 | 行业深度分析 | 最新可得 | 阶段证据不足 | 成长/成熟 |
| `prosperity_status` | 景气状态 | string | 是 | 行业数据/深度分析 | 最新报告期 | 景气证据缺失 | 改善/承压 |

## 输出原则

- 输出完整内容，不区分任何免费版和付费版。
- 输出必须是客户可读的 Markdown 报告。
- 报告头部必须使用三行口径说明，成分股数量不进入用户侧报告。
- 完整报告章节必须从 `## 1. 首席结论卡` 开始编号，不得出现 `## 0` 或 `## 0A`。
- 报告面向普通投资者，首席结论卡后必须输出 `术语速查`，只集中解释正文实际使用的核心财务/经营指标；默认候选包括 ARPU、CapEx、ASP、ROE、PE/PB/PS/PEG、CR3/CR5/HHI、FCF、CFO、TAM、库存周期、稼动率、毛利率、净利率。行业技术名词不得进入 `术语速查`，应在正文首次出现时就地解释。
- 首席结论卡必须输出研究决策锚点，且只能使用“优先验证、等待确认、谨慎观察、暂不强判断”四类非交易化表达。
- 主报告不得展示子 Skill 原始接口路径、内部临时字段、接口字段、行业分类编号、指数编号、endpoint、原始参数或调试信息。
- 不输出旧版证据矩阵，不使用字母证据等级。
- 每个章节都必须按“子 Skill 输出事实 -> 指标变化 -> 业务解释 -> 对行业/环节/公司的影响 -> 风险或反证”展开。
- 完整报告第 4-9 章必须使用“结论、关键证据、解释与影响、反证”短块结构；每章默认 2-4 条关键证据，避免长篇连续段落。
- 完整报告第 3 章必须包含独立 `行业介绍`，固定输出行业定义、多维分类体系和 200-300 字“行业生意特征”。
- 研报向量补证只对缺失维度执行；body `query` 只传关键词或短关键词短语，行业、公司、日期、机构、topK 不拼入 `query`。
- 公司池必须先生成候选池并完成实名代表公司校验；代表公司必须来自今日投资数据源或用户输入，不能凭空编造。
- 龙头型、弹性型、防御/高股息型、景气反转型、风险暴露型中有合格样本的类型才进入正式公司池；同一家公司只能占一个主类型，重复候选不得用于补齐完整性。
- 产业链章节必须包含 `产业链全景表`、`重点细分领域发展`、`产业链价值排序表` 和 `环节解读`；公司池归因写入 `主类型判定证据`，不另设表后归因小节；正式表格不得只输出短标签。
- 公司池正式表不展示 `剔除因子`；公司池表、代表公司深度分析和风险表不得原样重复同一组指标。
- 完整报告优先选择 1-2 家已验证且不重复代表公司做深度分析；无法补齐的类型、重复候选和证据缺口进入内部摘要。
- `company_pool_completeness_status` 内部枚举只使用 `complete` 或 `incomplete`；不要混用中文枚举。中文“完整/不达标”只用于用户侧解释。
- 子 Skill 返回的结构化数据、研报文本和用户资料必须分层标注。
- 研报文本进入正文或引用来源前必须校验 `source_refs` 三要素：发布时间、发布机构、研报标题；不完整的研报片段不得出现在正式报告引用来源。
- S1-S7 单模块请求使用统一单模块格式，不强行展开完整报告。
- 量化评分、评级、分位、集中度和盈利弹性有数据才输出；无数据、空结果或无法得出时正式报告省略，内部摘要记录缺口和处理方式。
- 行业比较、轮动和产业链排序表达为研究观察优先级、验证环节和风险条件，不输出配置建议、超配/低配或确定性推荐。
- 完整报告和单模块报告均需说明时效限制和历史规律局限。
