# 研报解读 Markdown 报告模板

本模板用于 `investoday-research-report-analysis` 主 Skill 汇总研报类原子 Skill 输出后生成默认 Markdown 研报解读报告。Markdown 是默认交付形态，也是 HTML 报告的内容母版：HTML 只能重排、可视化和压缩表达本 Markdown 已有内容，不得新增未经证据支持的结论。

默认只在对话中输出 Markdown；只有用户明确要求 `.md` 文件时，才额外生成 Markdown 文件。用户确认需要 HTML 后，再按 `assets/templates/output-html-report-template.md` 生成同源 HTML。

## 输出结构原则

- 用户报告采用“结论先行、舆情概览、观点风险合并、预测一表承载、来源附录收口”的结构。
- 所有报告必须先给结论卡片，再用一段样本口径摘要说明时间范围、研报数量、覆盖机构和最近研报日期；不在页面前部展示大块代表性研报清单。
- 近期研报舆情放在样本口径摘要之后、观点分析之前，聚焦核心内容、机会、风险、情绪倾向和关键事由；舆情为空时写明“当前样本未取得可用研报舆情”，不编造总结。
- “机构观点”和“分析与风险”统一合并为“研报观点、分歧与风险”，固定包含核心共识、主要分歧、关注重点/跟踪指标和主要风险。
- 主要分歧必须说明分歧各方分别怎么看；当前样本没有实质分歧时，不强行列分歧，可写“当前样本未发现明显观点对立”。
- 目标价、评级、EPS、净利润预测和预测修正统一进入“预测评级与盈利预测”模块；表格前必须有样本范围、目标价有效样本统计、评级分布、预测修正方向和可比性说明。
- 预测明细只保留一个表格。目标价平均值只基于可解析数值样本计算；空值、区间无法解析和非数字文本不纳入平均，并说明有效样本数。
- 具体研报标题、发布机构、发布日期、评级和目标价作为“数据来源与代表性研报”放在末尾附录，不作为前部大模块。
- 每个核心结论必须能追溯到研报来源、研报字段、证据片段、原子 Skill 标准输出、用户材料或明确的当前样本口径说明。
- 报告不得编造研报、机构观点、预测样本、片段证据、客户数据、接口字段或原子 Skill 未提供的结果。
- 报告不得输出买卖指令、收益承诺、自动交易、个股推荐结论或规避合规边界的表述。
- 报告不得暴露 API Key、token、本机绝对路径、内部接口名、字段名、技术命令、生成过程或调试信息。
- Markdown 报告末尾必须询问：`是否需要我继续基于内容生成HTML研究报告页？`

## 多 Skill 汇总规则

| 汇总场景 | 处理规则 | 输出要求 |
|---|---|---|
| 多个研报原子 Skill 均已执行 | 综合研报样本、研报舆情、机构观点、预测评级、证据片段和对比结论。 | 前部只写样本摘要；具体研报清单进入末尾来源附录。 |
| 原子 Skill 输出冲突 | 不静默覆盖；列出冲突项、涉及机构或研报、差异原因和暂定处理。 | 在“研报观点、分歧与风险”中说明。 |
| 原子 Skill 未执行 | 不用空结论填充。 | 写明未执行原因和对结论的影响。 |
| 当前样本覆盖有限 | 降低结论强度。 | 使用当前查询范围、已取得研报样本和后续可扩展条件说明。 |
| 舆情样本为空 | 不编造舆情概览。 | 写明当前样本未取得可用研报舆情。 |
| 预测样本不可比 | 不计算上调/下调占比。 | 仅展示当前样本和不可比原因。 |
| HTML 后续生成 | 以 Markdown 为唯一内容母版。 | HTML 只做可视化，不新增结论。 |

## 个股研报解读报告

个股报告使用通用骨架，重点要求：

- 结论卡片后只保留样本口径摘要，不单列“近期代表性研报”前置清单。
- “近期研报舆情”优先使用研报舆情输出；未取得舆情时说明缺口。
- “研报观点、分歧与风险”必须合并核心共识、主要分歧、关注重点/跟踪指标和主要风险。
- “预测评级与盈利预测”只保留一个明细表，并在表前给出样本范围、目标价有效样本统计、评级分布和预测修正方向。
- 代表性研报清单只放在“数据来源与代表性研报”。

## 指定研报解读报告

指定研报解读可以保留“研报信息”“核心摘要”“结构化信息”“证据链”等单篇研报特有章节，但若输出同对象的预测评级或多来源观点，仍需遵守以下规则：

- 近期代表性研报或同对象样本清单放在末尾来源区。
- 观点、分歧、关注重点和风险合并表达。
- 评级、目标价、EPS、净利润预测进入同一个结构化信息或预测表，不拆成多个相邻表格。

## 多篇研报对比报告

多篇对比报告应保留对比属性，但默认顺序也遵守“舆情先行、观点风险合并、预测一表承载、来源附录收口”：

- 对比范围在前部压缩为样本摘要。
- 共识与分歧统一进入“研报观点、分歧与风险”。
- 涉及评级、目标价或盈利预测时，只补充一个机构级预测明细表，包含“预测/评级变化”列。
- 冲突、缺口和样本局限放在观点风险模块或综合结论前，不另行生成多个重复风险模块。

## HTML 同源映射

- `结论卡片` 映射为 HTML 首屏摘要、关键指标卡或核心结论区。
- `样本口径摘要` 映射为报告元信息和样本指标卡，不映射为前置大表。
- `近期研报舆情` 映射为舆情概览卡。
- `研报观点、分歧与风险` 映射为观点风险主题卡，包含核心共识、主要分歧、关注重点/跟踪指标和主要风险。
- `预测评级与盈利预测` 映射为预测总结区和唯一预测明细表。
- `数据来源与代表性研报` 映射为 HTML Appendix、来源区或 footer 附近的来源表。
- `免责声明` 必须映射为 HTML footer 或附录。

HTML 不得新增 Markdown 中没有的观点、指标、来源或结论。

## 输出自检

- 是否先给出结论卡片。
- 是否只在前部展示样本口径摘要，而没有前置大块代表性研报清单。
- 是否将近期研报舆情放在观点风险之前；舆情为空时是否说明缺口。
- 是否将机构观点、分歧、关注重点和风险合并到同一模块。
- 是否没有强行生成不存在的分歧；若有分歧，是否说明各方分别怎么看。
- 是否仅输出一个预测评级与盈利预测明细表，并在表前说明样本范围、目标价统计、评级分布和趋势口径。
- 是否每个关键观点绑定来源机构、研报标题、发布日期或当前样本口径说明。
- 是否将代表性研报清单下沉到“数据来源与代表性研报”。
- 是否删除内部字段、接口名、技术命令、调试信息和文件路径。
- 是否包含非投资建议声明。
- 是否在末尾询问是否需要继续生成同源 HTML。
