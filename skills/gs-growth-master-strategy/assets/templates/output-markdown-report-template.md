# 多 Skill Markdown 综合报告输出模板

本模板用于主 Skill 汇总多个原子 Skill 输出后生成默认 Markdown 交付物。它也是 HTML 报告的内容母版：HTML 只能重排、可视化和压缩表达本 Markdown 已有内容，不得新增未经证据支持的结论。

默认只在对话中输出 Markdown；只有用户明确要求 `.md` 文件时，才额外生成 Markdown 文件。用户确认需要 HTML 后，再按 `assets/templates/output-html-report-template.md` 生成同源 HTML。

## 使用条件

- 主 Skill 需要编排多个原子 Skill，并输出综合结论、综合报告、POC 说明、客户可读材料或验收报告。
- 用户未明确要求 HTML 时的默认交付。
- 用户明确要求生成 `.md` 文件。
- 目标业务包需要统一沉淀输出契约，避免每个原子 Skill 各自维护报告格式。

## 输出边界

- Markdown 是主 Skill 最终综合输出，不是原子 Skill 的逐字拼接。
- 原子 Skill 只提供标准字段、局部判断、证据和风险；主 Skill 负责冲突消解、权重说明、最终汇总和客户可读表达。
- 不编造行情、财务、公告、研报、新闻、政策、客户数据、接口字段或原子 Skill 未提供的结果。
- 原子 Skill 输出冲突时，必须列出冲突项、来源、差异原因和暂定处理方式，不得强行合并成单一确定结论。
- 缺少数据或未执行原子 Skill 时，必须写明“未执行 / 数据不足 / 待确认”，不能用模糊形容词替代证据。
- 不输出买卖指令、收益承诺、自动交易、个股推荐结论或规避合规边界的表述。
- 不暴露 API Key、token、本机绝对路径、内部报错、生成过程或调试信息。

## 主 Skill 汇总规则

- 每个核心结论必须能追溯到至少一个原子 Skill 输出、用户材料、数据契约或明确的数据不足说明。
- 汇总时优先保留原子 Skill 的标准字段名，不随意改名；如需改名，必须在主 Skill 输出契约里说明映射关系。
- 原子 Skill 输出之间存在冲突时，必须保留冲突，不得静默覆盖。
- 同一数据维度由多个原子 Skill 重复提供时，以主 Skill 的 `references/data-reference/` 中确认口径为准。
- 原子 Skill 未执行时，不要用空结论填充；写明未执行原因。
- 汇总表格必须有字段名、单位、时间口径、来源和空值含义。

## HTML 同源映射

- `核心摘要` 可映射为 HTML 首屏摘要和指标卡。
- `原子 Skill 执行结果` 可映射为能力矩阵表或执行状态卡。
- `综合分析` 可映射为主题卡、图表卡和分章节内容。
- `冲突与缺口处理` 可映射为观察清单或风险卡。
- `数据来源与证据链` 可映射为 HTML 附录。
- `风险提示` 与 `免责声明` 必须映射为 HTML footer。

## 输出格式写法

当目标主 Skill 支持 Markdown 输出时，在其 `## 输出契约` 中写明：

```markdown
默认先在对话中输出 Markdown 综合报告。Markdown 必须遵守 `assets/templates/output-markdown-report-template.md`：主 Skill 汇总多个原子 Skill 的标准输出，包含核心摘要、输入与分析范围、原子 Skill 执行结果、综合分析、冲突与缺口处理、综合结论、数据来源与证据链、风险提示和免责声明。结论必须可追溯到原子 Skill 输出、用户材料、数据契约或数据不足说明；不得编造行情、财务、公告、研报、新闻、政策、客户数据或接口字段。回复末尾询问用户是否需要继续生成同源 HTML。
```

## 验收清单

- [ ] Markdown 有 H1 标题、报告日期、主 Skill、原子 Skill 数量和输出形态。
- [ ] 包含核心摘要、输入范围、原子 Skill 执行结果、综合分析、冲突与缺口、综合结论、数据来源、风险提示和免责声明。
- [ ] 每个核心结论都有原子 Skill 输出、数据来源、用户材料或数据不足说明。
- [ ] 原子 Skill 输出不是逐字堆叠，而是经过主 Skill 综合、去重和冲突处理。
- [ ] 原子 Skill 冲突、未执行、数据不足和待确认项被显式列出。
- [ ] 表格列名、单位、日期口径、空值含义和来源清楚。
- [ ] 未编造接口、字段、新闻、研报、公告、政策或客户数据。
- [ ] 未暴露 API Key、token、本机绝对路径、内部报错或生成过程。
- [ ] 默认只输出 Markdown；只有用户明确要求文件时才生成 `.md`。
- [ ] 回复末尾询问是否需要继续生成同源 HTML。
