# 用户输出规范

本文件仅约束最终对用户可见的答案如何表达，不影响内部数据获取、评分逻辑和分析步骤。

即使下游原子 skill 内部维护查询参数、字段或代码示例，最终用户可见输出也必须按本文件转写为业务语言；内部取数口径不得原样进入报告正文、表格字段或注释。

## 禁止项

最终输出中不得出现以下内容：

- 参数名、字段名、接口名、脚本路径
- 一级行业代码、行业代码等内部取数代码口径
- 技术口径说明
- 调试式表述
- 具体数据平台、接口、字段、内部研报标识和原文定位信息或内部调用细节
- “按某平台某日期估值数据”“某接口显示”“某字段返回”等工程或平台来源表述
- 买入、卖出、持有、加仓、减仓、满仓、清仓、止盈、止损等交易指令
- 目标价、上涨空间、收益率承诺、确定性涨跌判断或个性化仓位建议
- 历史人物相关口径、历史英文称呼、历史人物式表述、历史 slug 或相关变体；用户输入或旧模板中出现时，最终答案必须统一转写为“成长大师”或“成长投资方法论”
- 历史高倍成长俗称；用户输入或历史资料中出现时，最终答案必须统一转写为“成长股特征”

典型禁止示例：

- `industryCode`
- `一级行业代码`
- `行业代码`
- `swIndustryCode`
- `indexCode`
- `pe_ttm`
- 内部接口路径
- 内部数据表名
- 内部数据字段
- `beginDate`
- `pageNum`
- “某接口显示”
- “字段返回”
- “按某参数口径”
- “由某接口代表”
- “按东方财富 2026-06-12 估值数据”
- “某接口返回”
- “某字段显示”
- “建议买入”
- “继续持有”
- “目标价为”
- “上涨空间”
- 历史人物相关口径
- 历史英文称呼
- 历史人物式表述
- 历史 slug

## 推荐替代表述

- `industryCode` -> “所属一级行业”
- 内部接口路径 -> “公开资料”或“公开数据”
- 内部数据表名 -> “基础资料”或“公开资料”
- “接口证据” -> “公开财务数据”“行业预测数据”“公开披露信息”
- “字段显示” -> “数据显示”或“公开资料显示”
- 研报预测或风险来源 -> 可写为“代表性公开研报来源：日期，研报标题，发布机构，用途”

## 排版规范

- 单标的轻量可读版：以 `# 成长大师视角：股票名称（代码）成长简析` 开头
- 单标的完整分析：以 `# 成长大师视角：股票名称（代码）成长分析` 开头
- 单标的完整分析不得输出空的一级标题；首个非空行必须是 `# 成长大师视角：股票名称（代码）成长分析`
- 多标的分析不得输出空的总标题；每个标的各自使用 `# 成长大师视角：股票名称（代码）成长分析` 分组，全部标的之后如需对比，只追加 `## 简短对照结论`
- 主模块统一使用 `##`
- 模块内部优先使用带编号的大标题，例如 `## 一、标的基础信息 / 二、行业景气度分析`
- 每个大维度下的细分内容优先使用 `1. 2. 3.` 这种分点方式，不再重复生成同层级小标题

## 语言风格

- 面向投资分析读者，不面向开发者
- 结论优先，依据随后
- 可保留专业术语，但不得暴露实现细节
- 面向普通 C 端投资者时，使用短句、明确判断和通俗解释，避免过度研报化。
- 专业术语首次出现时要解释，例如 PEG、自由现金流、盈利兑现、成长大师六类公司、成长股特征。
- 每段建议不超过 4 行；不要堆砌指标，不要使用夸张、煽动或确定性语言。
- 若需说明依据，只能写成自然语言，例如：
  - “基于公开财务数据”
  - “结合行业预测与公开披露信息”
  - “结合行业景气与公司成长表现”

## 完整报告输出规范

完整报告仅在用户明确要求“完整分析”“全面分析”“深度分析”“查看完整分析”“五维度分析”或“六维度分析”时使用。完整报告不是轻量摘要，必须逐维度展开，并保留各 reference 的完整用户可见字段。

```markdown
# 成长大师视角：股票名称（代码）成长分析

## 一、标的基础信息
## 二、能力圈与框架适配
## 三、行业生命周期与成长空间评估
## 四、行业景气度分析
## 五、企业盈利增长预测
## 六、PEG估值与成长匹配度分析
## 七、成长股特征匹配分析
## 八、综合成长潜力判断与提示
```

完整报告约束：

- 第二部分读取 `01-能力圈与框架适配分析.md`，不得跳过框架适配和成长大师六类归类。
- 第三至第七部分分别嵌入 `02-06` 对应 reference 的完整输出格式，不得压缩成概括性段落。
- 第八部分只做综合收束，不替代、压缩或改写前六个维度。
- 若某维度暂无法判断，仍保留该 reference 的完整字段和表格，并在对应字段写“暂无法判断”“待后续数据复核”或“当前公开证据尚不足以支持强判断”。
- 多标的对比时，每个标的分别使用 `# 成长大师视角：股票名称（代码）成长分析` 作为一级标题；全部标的之后如需对比，只追加 `## 简短对照结论`。

完整报告验收清单：

- `## 二、能力圈与框架适配` 必须保留 `01` 的完整用户可见字段，不得只写适配结论。
- `## 三、行业生命周期与成长空间评估` 必须保留 `02` 的编号、字段名、字段式结论摘要、增长阶段特征表和暂无法判断占位；不得把生命周期压缩成几句概括。
- `## 四、行业景气度分析` 必须保留 `03` 的 `结论摘要 / 关键依据 / 评分口径说明 / 季节性说明 / 核心驱动 / 成长大师投资视角` 字段，以及 `总评分` 和 `各项计分`；核心指标必须按百分数展示并带 `%`。
- `## 五、企业盈利增长预测` 必须保留 `04` 的历史趋势、未来预测、三情景和关键假设字段；预测样本不足时保留表格占位；`研报依据` 必须按 `日期 / 研报标题 / 发布机构 / 用途` 逐条展示，不得合并成一整段。
- `## 五、企业盈利增长预测` 中只要出现未来预测净利润、未来预测增速、三情景预测或机构预测样本，必须同时出现 `研报依据` 表，且表头必须为 `日期 / 研报标题 / 发布机构 / 用途`；缺少该表时完整报告不合格，必须补齐后再输出。
- `研报依据` 不得因为样本不足、标题缺失或只定位到机构而省略；缺失单元格写“暂无可用数据”或“未能定位到具体标题，待后续数据复核”。
- `## 六、PEG估值与成长匹配度分析` 必须保留 `05` 的关键依据、三情景 PEG 表格、预测依据、适用边界和风险字段；预测依据来自研报查询时必须按 `日期 / 研报标题 / 发布机构 / 用途` 展示。
- `## 七、成长股特征匹配分析` 必须保留 `06` 的 10 项特征匹配表、综合评级、评级依据、核心优势、主要短板和方法论收束字段；评级依据只用自然语言说明核心匹配项和拖累项，不展示总分、状态数量或计算式。
- 任一维度缺字段、缺表格或缺“暂无法判断”占位时，必须补齐后再输出，不得用摘要段替代。

## 单维度输出规范

用户明确“仅调用”“只看”“单独分析”“只分析某维度”时，输出颗粒度不得低于完整报告中该维度的完整模板。

- 行业生命周期单维输出必须保留 `结论摘要 / 判断依据 / 主要风险 / 成长大师视角` 四段结构。
- 生命周期 `结论摘要` 必须使用字段式输出，不做表格；股票模式展示股票代码、股票名称、所属一级行业、背景对照行业、当前行业阶段和成长空间评级，行业直问只展示分析行业、当前行业阶段和成长空间评级。
- 生命周期 `增长阶段特征` 必须使用固定证据表，保留未来三年收入预测增速、未来三年净利润预测增速、T+1/T+2/T+3 净利润预测增速；缺失项写“暂无法判断”，不得删除行。
- 其他单维度调用同样必须保留对应 reference 的固定编号、字段名、表格和暂无法判断占位，不得输出摘要段替代完整模板。

## 轻量可读版公司分析输出规范

本规范用于券商 APP 普通 C 端默认展示。轻量版不是专业研报，也不是完整六维度报告；它是 `summary_fast` 快速画像，只从 `light-fast-summary.md` 的五个槽位和已取得证据中提炼用户最需要先理解的内容。

### 适用场景

- 用户普通询问单个 A 股公司，例如“用成长大师视角分析宁德时代”“看看贵州茅台怎么样”“诊断比亚迪是否值得研究”。
- 用户未明确要求“完整分析”“全面分析”“深度分析”“查看完整分析”“五维度分析”或“六维度分析”。
- 轻量版复用行业快照、财务快照、预测快照和估值快照中的摘要判断，不读取 `01-06` 完整维度 reference；必须获取近期机构预测样本摘要，但不得为补齐完整盈利预测、PEG 三情景、评级变动原因或成长股特征深层证据而默认触发重链路；轻量版未展开或未取得实际值的项目不写入用户可见报告，不使用“暂不展示”“暂无可用数据”“暂无足够数据”或同类占位话术。

### 输出总规则

- 使用 Markdown。
- 使用自然语言，不输出 JSON 元数据。
- 采用“总分总”：先给结论，再给理由，再给风险，最后用成长大师式通俗表达总结。
- 轻量版固定结构为：先说结论、核心判断表、三个核心理由、主要风险、反证信号、免责声明/说明、下一步可以继续了解。
- 每个核心段落必须采用“判断句 + 数据证据 + 方法论解释”的三段式表达，禁止只罗列事实后不解释其对成长判断的含义。
- 每个关键判断必须有依据；依据可来自财务指标、历史趋势、行业对比、公司公告、定期报告、监管公开信息、新闻资讯、估值分位、现金流数据或股权结构数据。
- 不允许在无数据支持时输出强判断；轻量版缺少某项事实时，优先省略该维度或降低结论置信度，不在用户可见报告中写“暂无足够数据”“暂无可用数据”等占位话术。
- 不得输出交易指令、目标价、上涨空间、收益承诺或确定性涨跌判断。
- 如果公司不适合用成长投资方法论框架分析，必须明确提示“框架适配度较低”或“需要降低分析置信度”。

### 核心判断枚举

- 生意可理解度：高 / 中 / 低
- 成长大师分类：缓慢增长型 / 稳健增长型 / 快速增长型 / 困境反转型 / 周期型 / 隐蔽资产型
- 成长线索：清晰 / 待验证 / 偏弱
- 行业阶段：初创期 / 成长期 / 成熟期 / 衰退期
- 行业景气趋势：上升 / 平稳 / 下降

### 核心理由规则

- 三个理由默认分别覆盖生意与行业、盈利与现金流、估值快照；PEG 与成长股特征只在本次已展开或用户明确追问时纳入理由三。

### 数据口径规则

- 轻量版和完整报告标题下必须输出固定数据口径行。数据口径行只列示已取得实际值的项目；轻量版已取到的行情估值日期、财务报告期和机构预测样本状态填实际返回值或样本摘要；行业估值深链路未展开时直接省略行业估值分句。完整报告必须先补齐必需链路；仍无法闭合时，不在标题下数据口径写占位，而在对应维度风险/边界中自然说明。
