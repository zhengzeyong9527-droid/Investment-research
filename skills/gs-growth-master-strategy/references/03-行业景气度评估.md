# 行业景气度评估

## 本文件定位

本 reference 承接成长大师行业景气度分析框架，负责在主 `SKILL.md` 编排下判断行业当前景气位置、景气边际变化、政策与供需驱动因素，并保留 1-5 分景气度评分、趋势判断和成长大师视角。它不是独立 skill；具体行业分析由 [行业分析](../references/gs-industry-analysis.md) 原子 skill 承载。

## 调用链路

1. 主 skill 读取本 reference 后，调用 [行业分析](../references/gs-industry-analysis.md) 获取行业深度分析结论。
2. [行业分析](../references/gs-industry-analysis.md) 按其内部规则调用 [行业数据查询](../references/gs-industry-analysis.md/skills/gs-industry-data/SKILL.md) 获取行业景气、预测、行情扩散、财务概览、竞争结构、政策监管和文本线索。
3. 本 reference 基于外部分析 skill 返回结果，叠加成长大师景气度、季节性修正、成长质量和风险边界判断。

这条链路是“成长大师 reference -> L2 分析 skill -> L1 查询 skill -> 数据服务 -> L2 返回标准输出 -> 成长大师方法论叠加”。

## 数据补充边界

若 [行业分析](../references/gs-industry-analysis.md) 返回结果缺少本 reference 必须使用的景气指标、预测、行情扩散、政策监管、供需事件或季节性验证证据，先由行业分析及其绑定的行业查询 skill 在内部补足；若仍缺少研报类文本证据，完整报告、行业景气单维度或用户明确追问时才消费 [研报数据查询](../references/gs-research-report-query.md) 的紧凑标准输出补充。个股模式下的“机构评级趋势”在完整报告或行业景气单维度中必须消费 [研报数据查询](../references/gs-research-report-query.md) 的预测评级和预测修正摘要标准输出，不得只因主行业数据包未包含该项就写成无法确认；`summary_fast` 轻量版不默认展开机构评级趋势，只写“预测修正暂不展示”。补充数据只服务于景气度判断，最终用户输出不得暴露接口名、参数名、字段名、内部研报标识和原文定位信息或脚本名。

外部分析 skill、行业查询 skill 或补充标准输出单点失败时，不得直接输出“数据服务不可用”。必须先做最小可用性探测：个股模式先确认股票可识别并取得所属行业；行业模式先确认行业对象可识别；随后尝试取得行业景气、行业财务概览、行业预测、行情扩散或公开文本线索中的任一核心证据。只要任一核心证据可得，就输出有限行业景气度分析，并把缺口写成业务化说明。

用户说“仅调用行业景气度”“只看行业景气度”时，限制的是成长大师主流程只执行本 reference，不执行生命周期、盈利预测、PEG 或成长股特征维度；不限制本 reference 内部为判断景气度而获取政策监管、供需事件、行情扩散、文本线索和季节性验证等必要证据。

## 保留的旧框架

以下输入、证据提取、评分和输出框架继续沿用成长大师分析需求；数据链路统一由 L2/L1 原子 skill 提供标准输出。

## 输入要求

### 可接受输入

- A 股股票代码或完整股票名称。
- 主 skill 或 `02-行业生命周期评估.md` 传入的行业上下文。
- 用户直接提出的行业景气度问题。

### 最小输入

- 个股模式：1 个可识别 A 股标的。
- 行业模式：行业名称或主 skill 传入的行业名称、代码、层级上下文。

### 推荐输入

- 复用前置步骤已确定的行业名称、代码和层级，避免重复识别。
- 行业直问保留用户原始行业词用于最终展示。

### 可选输入

- 可传入行业生命周期阶段、三级回退说明或前置行业归类结果。

### 默认假设

- 个股模式默认使用个股所属申万一级行业作为景气度分析口径。
- 行业模式默认优先复用主 skill 传入的内部取数行业代码。

### 输入校验

- 个股模式必须先确认标的是 A 股。
- 行业模式不得要求股票代码，也不得展示内部取数参数、行业层级后缀或接口字段。

### 缺失输入处理

- 无法识别标的或行业时，停止并要求补充更标准的股票或行业名称。
- 数据服务不可用时，按“失败处理”输出，不编造景气度评分。

### 示例输入

```text
分析 300750 宁德时代的行业景气度。
白酒行业景气位置怎么样？
```

### 反例输入

```text
分析宏观经济景气。
```

原因：本 skill 处理行业景气度，不处理泛宏观景气度。

## 触发方式

本文件不作为独立 Codex skill 触发，但支持由主 `SKILL.md` 单维度调用或全维度调用：
1. 用户要求完整成长大师分析时，作为第二个维度执行。
2. 用户明确只看行业景气度时，作为单维度 reference 执行。
3. 行业直问进入分析后，与 `02-行业生命周期评估.md` 配合形成行业维度结论。

单维度执行时，只输出本文件定义的“行业景气度分析”；不得追加行业生命周期、企业盈利预测、PEG估值或成长股特征评级结论。主包只请求行业分析原子 skill 的紧凑标准输出，不在本 reference 直接发起底层查询。

**上下文复用**：若由主 skill 或 `02-行业生命周期评估.md` 传入行业上下文，必须复用其中的实际分析行业名称、代码和层级。

## 输入模式

支持两种输入模式：

1. **个股模式**：输入股票代码/名称。若前置步骤未传入行业上下文，先通过股票所属行业获取行业代码；成长大师全维度分析或单维度景气度分析时，固定使用个股所属一级行业作为景气度分析口径。
2. **行业模式**：主 skill 已传入行业上下文，包括用户原始行业词、命中行业名称/代码/层级、内部取数行业名称/代码/层级、三级回退说明。行业模式不得要求股票代码，也不得展示股票代码/股票名称。

行业模式优先复用主 skill 或 `02-行业生命周期评估.md` 传入的用户原始行业词、规范化提示词和行业上下文，并由 [行业分析](../references/gs-industry-analysis.md) 通过 [行业数据查询](../references/gs-industry-analysis.md/skills/gs-industry-data/SKILL.md) 确认可用数据口径。用户可见输出必须使用用户原始输入的行业名称；若内部使用上级行业数据补足分析，只能用自然语言说明“以下结合该行业相关公开数据和上级行业数据进行分析”，不得展示规范化层级名称或内部取数口径。

## 数据获取

### 步骤1：获取行业分析结果

先调用 [行业分析](../references/gs-industry-analysis.md)，由其按输入模式通过 [行业数据查询](../references/gs-industry-analysis.md/skills/gs-industry-data/SKILL.md) 获取行业数据包并返回行业深度分析结果：

- 个股模式：用股票代码或完整股票名称查询股票所属申万行业；固定取一级行业作为景气度分析口径，二级/三级行业只作背景对照。
- 行业模式：用用户原始行业词和去后缀规范化提示词确认行业基础信息；按 [行业数据查询](../references/gs-industry-analysis.md/skills/gs-industry-data/SKILL.md) 的一级可直接取数、二级优先、三级回退二级规则确认可分析口径。
- 数据包至少尝试覆盖：行业财务概览、盈利/景气指标、行业预测、轮动/换手率、实时行情、行业成分股行情、研报/新闻/公告文本线索、政策监管事件和竞争结构辅助线索。

即使用户使用“仅调用”措辞，也必须至少尝试获取上面这些景气度支撑证据；“仅调用”不得被解释为只查询三项盈利环比指标。

若外部分析/查询链路返回多个候选行业，停止并要求用户确认；若无法识别行业，提示补充更标准行业名称或代表性公司。

### 步骤1A：最小可用性探测

当外部分析 skill 返回能力不可用、数据不可用、超时、空结果或无法确认时，不得立刻进入全局失败提示。按以下顺序做最小可用性探测：

1. 个股模式：先用股票名称或代码确认 A 股标的，并查询所属行业；若能取得所属行业，说明行业识别可用。
2. 行业模式：先用用户原始行业词确认唯一行业对象；若有多个候选，追问，不输出不可用。
3. 使用已确认行业对象尝试取得行业景气度数据；如果三级行业无结果，允许回退到二级或一级行业，并用自然语言说明“结合相关行业公开数据”。
4. 若行业景气度数据缺失，再尝试行业财务概览、行业预测、行情扩散、成分股表现或政策/事件文本线索中的任一核心证据。

最小可用性探测得到任一核心证据时，必须继续输出“行业景气度分析”。不得因为机构评级、政策事件、季节性验证或某个补充数据缺失而输出“国信证券数据服务暂不可用”。

若行业景气度数据已返回 `roeTtmQoqGrowth`、`grossMarginTTMMoMGrowth`、`ttmNetProfitMarginQoq`、报告年度或报告期，必须把最新一期可用值填入“关键依据”表格。不得把已取得的核心量化字段写成“数据不足”。只有字段真实为空、未返回、口径不可比或查询失败时，才在该单元格写“数据不足，无法判断”，并保留其他已取得字段。

个股模式下，行业景气度三项核心表必须来自行业景气度口径，不得用公司自身 ROE、毛利率、净利率替代。公司口径财务指标只能放在“趋势依据”或“综合说明”中作为龙头韧性背景，不能填入或替代行业景气度表格。

在数据服务已配置时，生成行业景气度表格前必须通过 [行业分析](../references/gs-industry-analysis.md) 及其内嵌 [行业数据查询](../references/gs-industry-analysis.md/skills/gs-industry-data/SKILL.md) 的标准输出取得最近一期行业景气度记录；若标准输出仍缺少该记录，表格中对应单元格写“暂无足够数据”。不得在本 reference 中维护或展示底层接口名，也不得把已返回的标准输出误写成“硬评分所需字段缺失”。

回归约束：对“仅调用行业景气度，分析贵州茅台”这类个股模式请求，若已识别到食品饮料或白酒相关行业并取得最近一期行业景气度记录，`ROE(TTM)环比增速`、`毛利率(TTM)环比增速`、`净利率(TTM)环比增速` 三行必须填入实际数值和环比变化；不得输出三行“数据不足，无法判断”。

### 步骤2：缺口数据补充

仅当 [行业分析](../references/gs-industry-analysis.md) 明确返回本 reference 必需维度缺口，且 [行业数据查询](../references/gs-industry-analysis.md/skills/gs-industry-data/SKILL.md) 仍未覆盖时，才按 `references/08-调用链路与数据补充.md` 调用 [研报数据查询](../references/gs-research-report-query.md) 补充库存、价格周期、ASP、原材料价格、价差、开工率、产能、供需缺口等公开研报文本线索。补充只用于完善行业景气度判断，不改变用户可见输出结构；最终答案不得出现底层接口名、参数名、字段名、内部研报标识和原文定位信息或技术调用细节。

个股模式可通过已安装分析/查询 skill 补充个股机构评级、季度收入利润、成长指标和公司前景文本等股票专属数据；若缺口属于公开研报文本线索，则调用 [研报数据查询](../references/gs-research-report-query.md) 标准输出。行业模式不得要求股票代码，也不得用无关个股数据替代行业数据。

最终答案不得把数据缺口写成执行过程，例如“本次未调用政策数据”“本次未调用事件数据”。若已按规则尝试但没有取得有效资料，写成“公开数据中暂未取得明确政策线索”“公开数据中暂未取得明确行业事件线索”或“该项证据不足，无法判断”。

### 步骤2A：机构评级趋势补充

评分项“机构评级趋势”只用于个股模式，只接受股票级可比预测修正样本，不接受研报热度、研报观点、单一代表公司或行业预测增速替代。行业直问模式不设置该评分项，硬评分总分为 4 分。

**个股模式链路**

个股模式下，评分项“机构评级趋势”必须按以下顺序补齐：

1. 完整报告或行业景气单维度调用 [研报数据查询](../references/gs-research-report-query.md) 的预测评级标准输出，使用 gs 返回的近 3 个月预测样本生成“预测修正摘要”；`summary_fast` 轻量版只获取预测样本摘要，不触发预测修正摘要和机构上调占比计算。
2. 预测修正摘要优先基于同一研报样本的本次预测值与上次预测值比较，默认比较 T+1 净利润预测；T+1 不可比时依次使用 T+2、T+3，同一条研报样本只计入一次。净利润预测不可比但 EPS 预测可比时，可使用同期限 EPS 作为补充，并在内部口径中标注。
3. 上调占比 = 上调样本数 / 可比预测修正样本数。可比预测修正样本数大于 0 且上调占比超过 50% 时，机构评级趋势得 1 分；可比样本数为 0 或上调占比未超过 50% 时得 0 分。
4. 预测评级变动标准输出只用于补充变动方向和原因；若它只返回单条或汇总记录，不能单独换算为近 3 个月上调占比。
5. 若近 3 个月存在有效预测样本但缺少上次预测值或同期限可比字段，用户可见的本次得分依据必须写明“近3个月预测样本可得，但可比预测修正样本不足，无法计算上调占比”。不得只写“近期预测样本无法确认上调占比超过50%”。

**行业直问链路**

行业直问模式下，行业分析和行业数据查询可以取得行业预测、行业景气、行情扩散、行业研报文本和政策/供需线索；这些证据只能用于趋势依据、未来展望、核心驱动和景气拐点信号，不得并入硬评分。

当前研报数据查询的预测修正摘要是股票级标准输出。行业直问不得为了补足机构评级趋势而临时挑选龙头股、代表股或单一研报样本来替代行业级口径；也不得把行业预测增速、研报覆盖热度或研报观点写成“机构评级趋势”。行业直问输出模板中不出现“机构评级趋势”评分项，用户可见硬评分固定为 4 分制。

### 步骤3：景气度证据提取

从行业数据包中提取以下证据：

- 核心评分指标：ROE(TTM)环比、毛利率(TTM)环比、净利率(TTM)环比；核心评分与用户可见表格仅围绕这三项指标展开。
- 财务背景：收入增速、利润增速、最近四季度 ROE、毛利率、净利率、资产负债率等，用于解释景气变化质量。
- 未来展望：行业预测、轮动因子、换手率活跃度、公开研报主题变化，用于判断未来 1-2 年景气方向。
- 核心驱动：政策监管、供需事件、库存周期、价格周期、ASP、原材料价格、价差、开工率、产能、供需缺口、招标线索、行情扩散度、领涨/领跌和成分股涨跌分布。
- 季节性验证：若季度数据足够，比较近年同季度收入、利润和成长指标；数据不足时标注“季度验证数据不足”，不得强行归因为季节性。

景气判断不得只凭单一概括结论；必须由盈利改善、财务背景、预测或行情/文本线索共同支撑。样本估算、文本线索和代理口径必须在用户可见答案中用自然语言标注边界。

## 景气度评分规则

| 维度 | 分项上限 | 评分依据 |
|------|:----:|----------|
| ROE(TTM)环比趋势 | 2 | 连续2期环比上行得2分；单期上行得1分；环比下行得0分 |
| 毛利率(TTM)环比趋势 | 1 | 环比上行得1分；持平或下行得0分 |
| 净利率(TTM)环比趋势 | 1 | 环比上行得1分；持平或下行得0分 |
| 机构评级趋势（仅个股模式） | 1 | 近3月可比预测修正样本上调占比>50%得1分；可比样本不足或未超过阈值记0分 |
| **个股模式总分** | **5** | **1-2分：低景气；3分：中性；4-5分：高景气** |
| **行业直问总分** | **4** | **0-1分：低景气；2分：中性；3-4分：高景气** |

硬评分只允许使用最近一期可得行业景气记录计算。若同一标的、同一问题、同一数据日期重复分析，必须复用同一行业口径和同一最新报告期；不得在一次输出中用一级行业、另一次输出中改用二级或公司自身口径来重算硬评分。个股模式下不得用公司自身 ROE、毛利率、净利率或财务质量指标替代行业景气指标。

评分项必须分别受分项上限约束，不得出现 `2/1`、`3/2` 等超过分项上限的表达。个股模式 `总评分` 必须固定写成 `ROE趋势x/2 + 毛利率趋势x/1 + 净利率趋势x/1 + 机构评级x/1 = x/5`；行业直问 `总评分` 必须固定写成 `ROE趋势x/2 + 毛利率趋势x/1 + 净利率趋势x/1 = x/4`，不得出现机构评级趋势评分项。用户可见的 `总评分` 中的分子与 `各项计分` 等号后的分子必须完全一致。若不一致，输出前必须以分项求和结果为准重算并改写 `总评分` 和景气等级；不得输出“总评分1/5、各项计分=2/5”这类矛盾文本。若某项关键数据不足，该项硬评分记为 `0/对应上限`，并在趋势依据或评分依据中说明数据不足；若数据已取得但未达到加分阈值，必须写“数据已取得但未达加分条件”，不得误写为“数据不足”。文本线索、政策事件、新闻、公开研报文本线索和行业事件只能用于趋势依据、未来展望和核心驱动解释，不并入硬评分。

用户可见的 `ROE(TTM)环比增速`、`毛利率(TTM)环比增速`、`净利率(TTM)环比增速` 必须统一按百分数展示，保留 1-2 位小数并带 `%`；若下游返回小数值（如 `0.0951`），必须换算为 `9.51%`，不得展示原始小数。

## 景气趋势判断

- **上升通道**：连续2期以上关键指标环比改善；个股模式可结合机构评级上调辅助验证
- **平稳运行**：指标小幅波动、无明显方向；个股模式可结合机构评级稳定辅助验证
- **下降通道**：连续2期以上关键指标环比下行；个股模式可结合机构评级下调辅助验证

## A股季节性因素修正

分析时需纳入以下A股特有季节性因素：
- Q1（春节效应）：消费、餐饮等季节性偏强；制造开工率偏低
- Q2（年报/一季报披露期）：业绩验证窗口，超预期/低于预期波动大
- Q3（中报披露期）：中期业绩验证
- Q4（年末冲量）：基建、地产年末集中结算

对景气度判断须刨除纯季节性扰动后再做趋势判定。

季节性修正必须给出数据依据：
- 若季度营收/利润波动与历史同季度规律一致，标注"主要为季节性扰动"，降低对景气趋势的权重。
- 若季度营收/利润显著偏离历史同季度规律，结合行业新闻、行业预测和成分股表现判断是否为景气拐点。
- 若季度数据缺失，标注"季度验证数据不足"，不得强行归因为季节性。

## 数据分析与结论生成规则

本节只用于内部分析检查，不定义用户可见的新结构。最终输出必须严格使用“输出格式”章节对应模式的标题、字段名和顺序，不得因为本节规则改写、合并、扩写或省略输出字段。

### 1. 结论摘要生成

- 结论摘要必须作为输出第一点。
- 当前景气水平只能使用：高 / 中 / 低。
- 当前趋势只能使用：上升通道 / 平稳运行 / 下降通道。
- 未来1~2年展望只能使用：上升 / 平稳 / 下行。
- 股票分析使用所属一级行业；行业直问使用用户原始输入的行业名称，不得混用。

### 2. 景气度判断

- 景气水平必须基于评分规则、行业预测、行情与文本证据综合判断。
- 趋势判断必须先核对时间口径，不得把单期波动直接写成趋势。
- 季节性说明必须保留，不得用季节性解释替代数据不足。
- 若指标之间方向不一致，只说明不一致和不确定性，不预设原因。

### 3. 成长大师投资视角

- 成长大师投资视角只输出与当前股票或行业景气状态相匹配的一条判断，不输出其他不适用情形。
- 判断依据优先来自当前景气水平、当前趋势、未来1~2年展望和已取得的行业阶段上下文；若行业阶段上下文缺失，只基于景气数据说明当前适配度，不补写生命周期结论。
- 不得在景气度 reference 中新增生命周期阶段判定、PEG、盈利预测或成长股特征评级结论。
- 不得输出“景气上行+成长期行业 / 景气下行+成熟期行业 / 周期型行业”三种通用情形清单。
- 若字段数据不足，保留字段并写“数据不足，无法判断”。

## 失败处理

- 行业景气度数据不足：提示"该行业景气度数据部分缺失，基于现有指标评估"，不补全缺失数据
- 所属行业信息缺失：提示"暂未获得完整行业信息，请确认前置分析步骤或公开资料是否完整"
- 行业模式下行业层级无法确认：提示"暂未能确认该行业的有效分析层级，请补充更标准的行业名称或代表性公司"
- 下游标准输出超时：提示"数据服务响应较慢，已获取部分数据，以下分析基于现有信息"
- 补充标准输出缺失：标注"部分补充数据缺失，政策事件与季节性判断基于已获取信息完成"，不阻断景气度评分
- 全局数据服务不可用：只有最小可用性探测中标的/行业识别、行业景气度、行业财务概览、行业预测、行情扩散和公开文本线索均不可得时，才允许返回主 skill 的统一不可用提示；不得把单个标准输出缺失升级为全局不可用。
- 新闻文本噪声较多：仅筛选与行业或公司直接相关事件，不引用无关新闻
