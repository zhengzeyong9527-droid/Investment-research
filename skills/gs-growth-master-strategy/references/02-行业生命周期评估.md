# 行业生命周期评估

## 本文件定位

本 reference 承接成长大师行业生命周期分析框架，负责在主 `SKILL.md` 编排下判断行业所处阶段（初创期/成长期/成熟期/衰退期）、成长空间、成长大师六类公司适配和风险识别。它不是独立 skill；具体行业分析由 [行业分析](../references/gs-industry-analysis.md) 原子 skill 承载。

## 调用链路

1. 主 skill 读取本 reference 后，调用 [行业分析](../references/gs-industry-analysis.md) 获取行业深度分析结论。
2. [行业分析](../references/gs-industry-analysis.md) 按其内部规则调用 [行业数据查询](../references/gs-industry-analysis.md/skills/gs-industry-data/SKILL.md) 获取行业口径、生命周期、景气、预测、行情、产业链、竞争结构、市场空间和政策监管线索。
3. 本 reference 基于外部分析 skill 返回结果，叠加成长大师生命周期、六类公司、成长空间和成长股特征高发土壤判断。

这条链路是“成长大师 reference -> L2 分析 skill -> L1 查询 skill -> 数据服务 -> L2 返回标准输出 -> 成长大师方法论叠加”。

## 数据补充边界

若 [行业分析](../references/gs-industry-analysis.md) 返回结果缺少本 reference 必须使用的生命周期、渗透率、市场空间、竞争结构、技术路线或政策监管证据，先由行业分析及其绑定的行业查询 skill 在内部补足；若仍缺少研报类文本证据，消费 [研报数据查询](../references/gs-research-report-query.md) 的紧凑标准输出补充。补充数据只服务于生命周期判断，最终用户输出不得暴露接口名、参数名、字段名、内部研报标识和原文定位信息或脚本名。

## 保留的业务框架

以下输入、证据提取、评分和输出框架继续沿用成长大师分析需求；数据链路统一由 L2/L1 原子 skill 提供标准输出。

## 输入要求

### 可接受输入

- A 股股票代码或完整股票名称。
- 主 skill 传入的行业上下文。
- 用户直接提出的行业生命周期问题。

### 最小输入

- 个股模式：1 个可识别 A 股标的。
- 行业模式：行业名称或主 skill 传入的行业名称、代码、层级上下文。

### 推荐输入

- 个股模式同时提供股票代码和名称。
- 行业模式提供用户原始行业词、内部取数行业名称和行业代码。

### 可选输入

- 可传入主 skill 已识别的一/二/三级行业层级、三级回退说明或前置行业归类结果。

### 默认假设

- 个股模式默认使用个股所属申万一级行业作为生命周期分析口径。
- 行业模式默认优先复用主 skill 传入的内部取数行业代码。

### 输入校验

- 个股模式必须先确认标的是 A 股。
- 行业模式不得要求股票代码，也不得在用户可见输出展示内部取数参数。

### 缺失输入处理

- 无法识别标的或行业时，停止并要求补充更标准的股票或行业名称。
- 数据服务不可用时，按“失败处理”输出，不编造生命周期阶段。

### 示例输入

```text
分析 300750 宁德时代的行业生命周期。
锂电池行业处于什么阶段？
```

### 反例输入

```text
分析这个公司行业阶段。
```

原因：缺少可识别标的或行业名称。

## 触发方式

本文件不作为独立 Codex skill 触发，但支持由主 `SKILL.md` 单维度调用或全维度调用：
1. 用户要求完整成长大师分析时，作为第一个维度执行。
2. 用户明确只看行业生命周期时，作为单维度 reference 执行。
3. 行业直问进入分析后，与 `03-行业景气度评估.md` 配合形成行业维度结论。

单维度执行时，只输出本文件定义的“行业生命周期分析”；不得追加行业景气度、企业盈利预测、PEG估值或成长股特征评级结论。主包只请求行业分析原子 skill 的紧凑标准输出，不在本 reference 直接发起底层查询。

## 输入模式

支持两种输入模式：

1. **个股模式**：输入股票代码/名称。先获取股票基础信息和所属行业；成长大师全维度分析或单维度生命周期分析时，固定使用个股所属一级行业作为分析口径。
2. **行业模式**：主 skill 已传入行业上下文，包括用户原始行业词、命中行业名称/代码/层级、内部取数行业名称/代码/层级、三级回退说明。行业模式不得要求股票代码，也不得展示股票代码/股票名称。

行业模式优先复用主 skill 传入的用户原始行业词和规范化提示词，并由 [行业分析](../references/gs-industry-analysis.md) 通过 [行业数据查询](../references/gs-industry-analysis.md/skills/gs-industry-data/SKILL.md) 确认行业层级与可用数据口径。用户可见输出必须使用用户原始输入的行业名称；若内部使用上级行业数据补足分析，只能用自然语言说明“以下结合该行业相关公开数据和上级行业数据进行分析”，不得展示规范化层级名称或内部取数口径。

## 数据获取

### 步骤1：获取行业分析结果

先调用 [行业分析](../references/gs-industry-analysis.md)，由其按输入模式通过 [行业数据查询](../references/gs-industry-analysis.md/skills/gs-industry-data/SKILL.md) 获取行业数据包并返回行业深度分析结果：

- 个股模式：用股票代码或完整股票名称查询股票所属申万行业；固定取一级行业作为生命周期分析口径，二级/三级行业只作背景对照。
- 行业模式：用用户原始行业词和去后缀规范化提示词确认行业基础信息；按 [行业数据查询](../references/gs-industry-analysis.md/skills/gs-industry-data/SKILL.md) 的一级可直接取数、二级优先、三级回退二级规则确认可分析口径。
- 行业代码优先规则：完成行业识别后，所有支持行业代码入参的数据接口都必须优先传行业代码，不得优先使用行业名称、关键词或标题模糊检索。个股模式固定使用一级行业代码作为生命周期主口径；二级/三级行业仅作背景时，只有对应接口明确要求二级代码才传二级代码。
- 数据包至少尝试覆盖：行业基础信息、行业财务概览、盈利/景气指标、行业预测、行业行情、研报/新闻/公告文本线索、市场空间/政策监管、产业链、竞争结构摘要、机构覆盖/机构偏好辅助线索。
- 文本线索取数顺序：研报文本线索统一通过 [研报数据查询](../references/gs-research-report-query.md) 的标准输出补充；一级行业优先传入已确认一级行业范围，二级行业仅在前置行业识别明确时使用二级行业范围。行业新闻仍由行业数据查询能力按行业代码获取。不得用行业名称关键词作为首选口径；只有代码范围无结果且需要补充文本线索时，才可降级使用标题/关键词检索，并必须标注为补充线索。

若外部分析/查询链路返回多个候选行业，停止并要求用户确认；若无法识别行业，提示补充更标准行业名称或代表性公司。

### 步骤2：缺口数据补充

仅当 [行业分析](../references/gs-industry-analysis.md) 明确返回本 reference 必需维度缺口，且 [行业数据查询](../references/gs-industry-analysis.md/skills/gs-industry-data/SKILL.md) 仍未覆盖时，才按 `references/08-调用链路与数据补充.md` 调用 [研报数据查询](../references/gs-research-report-query.md) 补充对应研报文本证据。补充只用于完善行业生命周期判断，不改变用户可见输出结构；最终答案不得出现底层接口名、参数名、字段名、内部研报标识和原文定位信息或技术调用细节。

股票专属的基础资料、治理风险、资产负债、质押、处罚、财务实力、主营产品与个股产业链补充数据仅在个股模式中按已安装查询 skill 或非研报类补充口径补充；这些数据不用于行业直问模式。

机构覆盖/机构偏好辅助线索补充规则：
- 个股模式可使用目标股票或行业头部代表公司经 [研报数据查询](../references/gs-research-report-query.md) 返回的预测评级标准输出，观察覆盖样本数量、近期新增覆盖和覆盖变化趋势；该口径用于判断个股或头部公司的机构关注度，不得写成全行业机构覆盖率。
- 个股模式可补充目标股票或行业头部代表公司的机构持股统计，观察机构持股比例、基金/QFII/保险/社保等分项持股和增减持趋势；该口径只能作为机构偏好和筹码结构辅助线索。
- 行业模式可使用行业持仓的基金列表和行业持仓比例，观察基金对该行业的配置热度；该口径只能作为基金偏好代理，不得等同于“机构覆盖饱和”。
- 若缺少研报覆盖数量、机构持股或基金行业配置数据，应在成熟期判据中写“机构覆盖暂无法判断”，不得仅凭知名度、行业热度或主观印象判断“机构覆盖饱和”。

### 步骤3：生命周期证据提取

从行业数据包中提取以下证据：

- 增长阶段：行业预测、收入/利润增速、盈利改善方向、公开研报文本线索对渗透率、TAM/SAM、市场规模或成长阶段的描述。
- 行业竞争格局：竞争结构摘要、头部企业线索、样本集中度、CR3/CR5、进入壁垒、价格战或替代风险文本线索。
- 政策与景气背景：景气指标、行情扩散度、政策监管事件、市场空间与需求特征文本线索。
- 产业链与技术路径：产业链上下游、产品关系、技术路线、技术迭代、替代风险、资本开支或牌照准入线索；若仅来自公开研报文本线索，必须标注为样本或文本线索。
- 机构覆盖与偏好：研报覆盖机构数、近期新增覆盖、覆盖趋势、机构持股比例、基金行业配置数量和持仓比例；若只取得代表性股票数据，必须标注为“头部公司代理观察”或“代表性样本观察”。

生命周期、周期属性、需求刚性、需求频率、价格弹性、抗周期能力、替代风险和竞争格局属于文本抽取与规则化判断，不得写成官方行业分类或直接接口字段。

## 生命周期判定规则

| 阶段 | 核心特征 | A股本土化判据 |
|------|----------|-------------|
| **初创期** | 行业渗透率<5%，技术路径未定，多数企业亏损 | 机构覆盖极少、营收增速高但利润为负、政策初期扶持 |
| **成长期** | 渗透率5%-30%，增速20%+，竞争格局形成 | 机构覆盖快速增加、ROE/毛利率环比上行、政策持续加码 |
| **成熟期** | 渗透率30%-70%，增速趋缓至行业平均，龙头格局稳定 | 机构覆盖饱和、ROE/毛利率趋稳、行业整合并购增多 |
| **衰退期** | 渗透率>70%或需求萎缩，增速<GDP，产能过剩 | 机构覆盖下降、ROE/毛利率环比持续下行、政策限制性 |

技术路径与产业链补充判据：
- 若主营产品收入/毛利集中度高，且产业链关系显示上下游依赖稳定，可作为成长/成熟阶段的辅助证据，但不能替代行业渗透率和行业增速。
- 若主营产品对应的上下游关系复杂、替代产品多、研发费用排名靠前但盈利指标尚未改善，应在初创期/成长期判断中强化技术迭代风险提示。
- 若主营产品毛利贡献下降、产业链关系显示核心产品被替代或下游需求弱化，应在成熟期/衰退期判断中强化需求和技术替代风险。
- 若未取得主营产品、产业链或研发投入标准输出，不得编造技术路线、专利、研发管线或产业链证据，仍按行业分类、景气度和机构覆盖完成主判定。
- 成熟期判据中的“机构覆盖饱和”必须由研报覆盖数量/变化趋势、机构持股统计或基金行业配置数据支撑；只有代表性头部公司数据时，只能写“头部公司机构关注度较高/较稳定”，不得直接写“行业机构覆盖饱和”。

## 与成长大师六分类的适配

- **初创期行业** → 通常不属于成长投资偏好范围（高不确定性），仅极少数快速增长型潜在标的
- **成长期行业** → 对应快速增长型、部分困境反转型（成长大师最偏好阶段，成长股特征高发土壤）
- **成熟期行业** → 对应缓慢增长型、稳健增长型、周期型、隐蔽资产型
- **衰退期行业** → 成长大师一般不推荐，除非存在困境反转或隐蔽资产逻辑

本节是生命周期阶段与成长大师投资偏好的适配关系，不是 `典型归类` 字段的直接输出模板。`典型归类` 必须回答“该行业/标的所属行业在成长大师六类公司框架中更接近哪一类”，不得写成生命周期阶段，也不得自造“结构性成长/周期成长混合型”等不在成长大师六分类中的标签。

`典型归类` 的优先来源：
- 若输入为个股模式，先取个股所属申万一级行业，再按 `references/growth-master-six-types.md` 映射到成长大师六分类。
- 若输入为行业模式，先确认可分析的公开行业分类；能映射到申万一级行业时，按同一映射文件输出成长大师六分类。
- 若行业名称过细、跨多个一级行业，或映射文件没有覆盖，`典型归类` 写“暂无法判断”，并在 `综合说明` 中说明口径尚未闭合，不得临时创造新分类。
- 可输出的成长大师六分类名称仅限：缓慢增长型、稳健增长型、快速增长型、困境反转型、周期型、隐蔽资产型。`典型归类` 只能填写一个标准类名；不得输出辅助分类、多类型组合或自造标签。如存在第二属性，只能在 `综合说明` 或 `主要风险` 中用自然语言解释。

生命周期阶段与成长大师六分类可能不完全一致。生命周期回答“行业当下处于初创/成长/成熟/衰退哪个阶段”，`典型归类` 回答“按成长大师六类公司框架更接近哪类”。当二者看起来存在张力时，不得改写任一字段来消除张力，应在 `综合说明` 用自然语言解释两套口径的差异。例如：某一级行业按 A 股成长大师行业映射属于快速增长型赛道，但当前生命周期证据显示其已从早期高速渗透进入成熟整合阶段。该示例只说明写法，不得作为所有快速增长型行业的固定结论。

## 数据分析与结论生成规则

本节只用于内部分析检查，不定义用户可见的新结构。最终输出必须严格使用“输出格式”章节对应模式的标题、字段名和顺序，不得因为本节规则改写、合并、扩写或省略输出字段。

### 1. 结论摘要生成

- 结论摘要必须作为输出第一点。
- 生命周期阶段只能使用：初创期 / 成长期 / 成熟期 / 衰退期。
- 成长空间评级只能使用：高 / 中 / 低。
- 股票分析使用股票字段；行业直问使用用户原始输入的行业名称，不得混用。

### 2. 生命周期判定

- 生命周期阶段必须由行业增速、渗透率、竞争格局、盈利能力、政策与文本证据共同判断。
- 单一数据项不得直接决定阶段；暂无法判断时保留字段并说明“暂无法判断”。
- 若证据之间冲突，只说明冲突和不确定性，不强行给出确定性解释。

### 3. 成长大师视角判断

- 成长大师视角只做收束判断，不新增段落结构。
- 必须保留固定字段 `典型归类`、`是否属于成长投资核心关注方向`、`综合说明`。
- `典型归类` 必须填写一个成长大师六分类标准类名；不得填写生命周期阶段，不得填写“成熟期中的结构性成长”“周期成长混合型”“以X型为主兼具Y型特征”等非标准或多类型分类。
- `是否属于成长投资核心关注方向` 应结合 `典型归类` 与 `当前行业阶段` 同时判断：快速增长型且仍处于成长期通常为“是”；快速增长型但已进入成熟整合期可为“是”，但必须降低表述强度；衰退期通常为“否”，除非存在明确困境反转或隐蔽资产逻辑。
- `综合说明` 必须同时交代两件事：一是成长大师六分类的来源或依据，二是生命周期证据对当前阶段的修正。若二者看起来不一致，必须显式说明这是“分类映射口径”和“生命周期证据口径”的差异，不得让用户误以为字段冲突或模型自相矛盾。
- 不得在生命周期 reference 中新增 PEG、盈利预测或成长股特征评级结论。

## 输出格式

最终对用户可见的文本需遵守 `references/07-综合输出与表达规范.md`。

股票分析的结论摘要使用股票字段；行业直问的结论摘要使用用户原始输入的行业名称，不输出股票字段。

```

1. 结论摘要
   股票代码：xxx
   股票名称：xxx
   所属一级行业：xxx
   背景对照行业：二级行业为 xxx，仅作背景对照
   当前行业阶段：初创期/成长期/成熟期/衰退期
   成长空间评级：高/中/低
2. 判断依据
   增长阶段特征：

   | 指标 | 数值/趋势 | 含义 |
   |---|---:|---|
   | 未来三年收入预测增速 | xx.xx% | 判断行业需求扩张速度 |

```

输出强制约束：
- 必须完整保留对应模式的编号和字段名。
- `结论摘要` 使用固定字段式输出，不做表格；股票分析保留股票代码、股票名称、所属一级行业、背景对照行业、当前行业阶段和成长空间评级，行业直问只保留分析行业、当前行业阶段和成长空间评级，不得混入股票字段。
- `增长阶段特征` 必须优先使用固定证据表，保留未来三年收入预测增速、未来三年净利润预测增速、T+1/T+2/T+3 净利润预测增速五行；若某项指标缺失，对应单元格写“暂无法判断”，不得删除该行。
- `行业竞争格局`、`主营产品与产业链证据`、`政策与景气背景` 和四项 `主要风险` 继续使用字段式输出，每项控制为 1 段，不得把多个字段合并成一个长段。
- 若某字段暂无法判断，写“暂无法判断”，不得删除字段。
- 不得把 `成长大师视角` 改写为自由段落；必须保留 `典型归类`、`是否属于成长投资核心关注方向` 和 `综合说明` 字段。
- `典型归类` 字段只写成长大师六分类结果；生命周期阶段只写在 `当前行业阶段` 字段。
- 不得把示例句固化为通用答案；示例只能用于说明当成长大师六分类与生命周期阶段存在张力时，`综合说明` 应解释两套口径差异。

## 失败处理

- 数据缺失时：提示"该股票部分行业数据暂不可得，以下判断基于现有公开信息整理"，不强行编造
- 代码无效时：提示"未能识别该股票代码，请确认输入正确的A股6位代码"
- 行业模式下行业层级无法确认：提示"暂未能确认该行业的有效分析层级，请补充更标准的行业名称或代表性公司"
- 下游标准输出异常时：提示"数据服务暂时不可用，请稍后重试"，不返回错误JSON原文
- 补充标准输出缺失：标注"部分补充数据缺失，风险提示基于已获取信息完成"，不阻断生命周期主判定
