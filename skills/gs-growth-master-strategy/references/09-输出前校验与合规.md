# 成长大师 Skill 评审清单

结构性修改后，按本清单做人工文件检查，确认 skill 框架、reference 编排和外部 skill 调用链路一致。

## Frontmatter

- 必须包含 `name`、`title`、`version`、`description`、`tags`。
- `description` 必须包含清晰的 Use when 与 Do not use when 边界。
- 需要数据访问时，`requirements.skills` 必须声明当前主 skill 直接编排的外部分析/查询 skill。
- `metadata.clawdbot.requires.skills` 必须与 `requirements.skills` 保持同步。

## 输入契约

- 主 `SKILL.md` 必须包含 `## 输入要求`；各 reference 保留对应维度的输入约束、证据规则和输出框架。
- 章节应覆盖：可接受输入、最小输入、推荐输入、可选输入、默认假设、输入校验、缺失输入处理、示例输入、反例输入。
- 输入缺失或存在歧义时，应先停止或要求补充，不得猜测标的、行业或分析范围。

## 意图路由

- 主 skill 必须包含唯一的 `## 意图路由` 章节。
- 每个 route 应明确：用户意图、典型信号、必要输入、工作流和输出。
- 路由规则必须与 `## 输入预检` 一致；命中某个 route 后，不得继续落入后续 route。
- 普通单股分析必须默认进入 `single_stock_light_readable`；只有明确“完整分析 / 全面分析 / 深度分析 / 查看完整分析 / 五维度分析 / 六维度分析”时才进入 `single_stock_full_flow`。

## 依赖声明

- 主 skill 必须声明直接依赖的外部 skill；reference 只描述调用链路，不再声明本地子模块依赖。
- 数据访问链路必须符合 `references/08-调用链路与数据补充.md`：reference 调用分析 skill，分析 skill 调用查询 skill，查询 skill 通过接口取数；查询 skill 未覆盖但成长投资方法论框架必须使用的数据，先判断是否属于研报类缺口，研报类缺口统一调用 [研报数据查询](../references/gs-research-report-query.md) 标准输出补充。
- 不得把本机绝对路径写成长期规则。
- 数据缺失、接口失败、非 A 股边界必须有停止或标注规则，不得编造数据。

## 输出与风险

- 用户可见输出必须遵守 `references/07-综合输出与表达规范.md`。
- 最终报告不得暴露接口名、参数名、字段名、内部路由细节、内部研报标识和原文定位信息或原始调用命令。
- 最终报告不得出现历史人物相关口径、历史英文称呼、历史人物式表述、历史 slug 或相关变体；标题、方法论说明、总结、小结和一句话结论必须统一使用“成长大师”或“成长投资方法论”。
- 用户输入、历史资料或旧模板中的高倍成长俗称，最终答案必须统一转写为“成长股特征”；不得原样输出该类俗称。
- 输出前必须检查公司类型字段：`成长大师分类`、`典型归类`、`公司类型` 只能包含一个标准类名（缓慢增长型、稳健增长型、快速增长型、困境反转型、周期型、隐蔽资产型）或“暂无法判断”。不得出现稳定增长型、成熟稳健型、资产机会型、结构性成长型、周期成长型、以X型为主兼具Y型特征、X/Y混合型等非标准或多类型表达；第二属性只能进入依据、风险或反证信号。
- 输出前必须检查是否第一段已有明确结论、是否包含核心判断表、核心判断表是否覆盖公司类型/成长线索/估值匹配/最大风险、是否至少有 5 个关键数据支撑判断、是否写明 2-3 个可跟踪反证信号、是否区分历史事实/预测样本/方法论推断、是否解释 PEG 口径与适用边界。
- 标题下必须使用固定数据口径：仅基于 gs 数据，并且只列示已取得实际值的行情估值最近交易日、行业估值最近交易日、财务数据最近报告期和机构预测样本口径。`summary_fast` 轻量版必须获取近期机构预测样本摘要；样本为空或行业估值深链路未展开时，直接省略对应分句，不写“暂不展示”“暂无可用数据”“暂无可用预测样本”或同类占位。不得写成未经当前链路逐项校验的“投资者关系、年报、季报”等资料清单。
- 输出前必须检查数据口径行：不得出现 `xxxx`、`YYYY`、尖括号、方括号、花括号、“暂不展示”“暂无可用数据”“暂无足够数据”“暂无可用预测样本”或“按数据口径规则生成”等占位内容；缺失日期或报告期时删除该分句，必要时在对应维度正文中用自然语言说明研究边界。
- 输出前必须区分“未返回”和“不适用”：行业指数估值已返回日期但行业 PE 为负数或为 0 时，数据口径中的 `行业估值截至` 必须填写实际日期，不得写“暂无可用数据”；行业基准 PEG 状态写“不适用”或按一级回退口径展示。
- 研报补充证据在用户可见输出中统一归入“gs 返回的近期预测样本”或“文本线索”；需要溯源时只展示日期、研报标题、发布机构和用途，不得展示底层研报接口名、参数名、内部报告编号或原文定位信息。
- 企业盈利预测和 PEG 估值凡使用研报预测样本、预测修正摘要或研报观点风险，输出前必须保留研报依据表格；表头固定为 `日期 / 研报标题 / 发布机构 / 用途`，只展示这四列。若日期、标题或机构缺失，保留表格并写“暂无可用数据”或“未能定位到具体标题，待后续数据复核”，不得省略来源表。
- 完整报告、盈利预测单维度和 PEG 单维度必须执行研报依据硬门禁：若企业盈利预测章节出现未来预测、三情景预测、机构预测样本、预测修正摘要、PEG 预测依据或研报观点风险，但章节内没有 `研报依据` 表格，必须视为输出不合格并补齐；不得用“近期机构预测样本”“代表性研报较多”等散文替代表格。`summary_fast` 轻量版只输出预测样本摘要时不要求研报依据表。
- `研报依据` 表格的用户可见表头必须包含且只包含 `日期 / 研报标题 / 发布机构 / 用途`；表头缺列、改名为“来源/机构/标题”、合并成自然段或只有脚注说明，均视为未通过硬门禁。
- 研报向量片段只能作为辅助文本证据；若片段缺少对象、时间、指标、数值或明确方向，必须写“暂无足够数据”，不得转写为确定结构化字段。
- 行业生命周期输出必须保留原四段结构：`结论摘要 / 判断依据 / 主要风险 / 成长大师视角`；`结论摘要` 必须为字段式输出，不做表格；`增长阶段特征` 必须包含固定证据表。
- 生命周期增长阶段特征表必须保留未来三年收入预测增速、未来三年净利润预测增速、T+1/T+2/T+3 净利润预测增速五行；缺失项写“暂无法判断”，不得删除行或改成散文概括。
- 生命周期股票模式不得漏股票代码、股票名称、所属一级行业和背景对照行业；行业直问不得混入股票代码、股票名称或个股字段。
- 行业景气度硬评分按场景区分：个股模式使用 ROE、毛利率、净利率和机构评级四项；行业直问只使用 ROE、毛利率和净利率三项。公开研报文本线索不得并入硬评分。
- 不得输出投资建议、买卖指令、持有建议、目标价、上涨空间、收益承诺、确定性预测或个性化仓位建议。
- 完整报告和多标的报告不得输出空的一级标题；单标的完整报告必须以 `# 成长大师视角：股票名称（代码）成长分析` 开头，多标的每个标的必须各自使用该一级标题。
- 行业归类用户可见输出不得输出一级行业代码、行业代码或内部取数代码，只保留行业名称、成长大师分类和简要逻辑。
- 行业景气度评分不得超过分项上限；个股模式各项计分必须写成 `ROE趋势x/2 + 毛利率趋势x/1 + 净利率趋势x/1 + 机构评级x/1 = x/5`，行业直问各项计分必须写成 `ROE趋势x/2 + 毛利率趋势x/1 + 净利率趋势x/1 = x/4`；文本线索不得并入硬评分；`总评分` 必须与各项计分等号后的总分一致，不一致时按分项求和重算；核心指标值和环比变化必须按百分数展示并带 `%`。
- 行业景气度必须输出 `评分口径说明`；个股模式解释 ROE趋势、毛利率趋势、净利率趋势和机构评级趋势，行业直问只解释 ROE趋势、毛利率趋势和净利率趋势。
- 个股完整报告或行业景气单维度下，行业景气度的“机构评级趋势”必须优先消费研报查询原子 skill 返回的股票级预测修正摘要；可比样本可得时必须展示近3个月可比预测修正样本数、上调样本数和上调占比。只有无预测样本、缺少上次预测值或同期限不可比时，才允许写无法计算，并必须说明具体原因；不得只写“近期预测样本无法确认上调占比超过50%”。`summary_fast` 轻量版不展开该项。
- 行业直问下不得出现“机构评级趋势”评分项，不得用单一代表股、行业研报热度、行业预测增速或研报观点替代该项；行业直问硬评分固定为 4 分制。
- 企业盈利预测的 `预测口径` 若涉及预测修正或机构上调占比，必须把预测修正摘要合并进 `预测口径`，不得另起流程化小节；可比样本不足时必须说明具体缺口。
- 成长股特征综合评级必须由 10 项匹配状态内部计算得出；`暂无法判断` 项达到 5 项及以上时优先输出 `暂无法判断`，否则按 `高 >=7.0 且不符合不超过2项 / 中 >=4.0且<7.0 / 低 <4.0` 判断；用户可见只输出综合评级和自然语言评级依据，不展示总分、状态数量或计算式。
- 行业 PEG 校验必须确认：PEG 输出已出现行业名称；已按“稳定对比行业 -> 同体系二级行业 -> 行业指数 PE -> 同口径行业基准预测增速 -> 行业基准 PEG”链路处理；只有二级行业无法形成有效行业基准 PEG 时才允许一级回退，并在用户可见输出写明“一级回退口径”。二级行业 PE 为负数或为 0 时属于“公式不适用”，不得写成“行业估值未返回”“行业当前 PE 未返回”或“行业基准 PEG 未返回”；必须继续检查一级行业回退是否可用。不得用行业 PE/PB/PS 五年分位替代当前 PE。
- 行业估值日期硬门禁必须确认：完整报告、PEG 单维度和成长股特征单维度只要已取得稳定对比行业、行业归属或行业代码，且最终数据口径缺少行业估值日期，必须先核对估值分析紧凑标准输出是否已完成“稳定对比行业 -> 同体系二级行业 -> 行业指数估值最近交易日”链路；若只取得行业 PE/PB/PS 五年分位、行业行情统计、行业景气或行业实时行情，不得通过该门禁。`summary_fast` 轻量版只做一次可得性尝试，未取得实际日期时省略行业估值分句，不阻断最终输出。
- 行业估值日期与行业基准 PEG 状态必须分离校验：行业指数估值已返回日期但行业 PE 为负数、为 0 或缺少同口径行业预测增速时，数据口径必须填写实际行业估值日期，行业基准 PEG 状态另写“不适用”或“待后续数据复核”；不得因 PEG 算不出来而把行业估值日期写成未返回。
- 行业侧默认只输出行业基准 PEG，个股乐观/中性/悲观三行均对比同一个行业基准 PEG；不得把不同期限字段拼接为行业侧三档 PEG。若输出行业侧三档 PEG，必须说明底层存在同一预测期限、同一行业层级下的高 / 中 / 低预测情景。
- 行业 PEG 缺失原因必须区分：二级行业无法解析、二级行业 PE 缺失、二级行业 PE 为负数或为 0 导致不适用、二级行业基准预测增速缺失/为负/接近零/口径冲突、一级回退也不可用。若一级回退 PE 与预测增速均有效，必须输出一级回退行业基准 PEG；用户可见不得展示行业代码、接口名、参数名或原始字段名。

### 完整报告验收

- 单标的完整报告必须以 `# 成长大师视角：股票名称（代码）成长分析` 开头。
- 第二至第七部分必须分别保留 `01-06` 对应 reference 的编号、字段名、表格和“暂无法判断”占位。
- 生命周期部分必须包含 `02` 的字段式结论摘要和增长阶段特征表；缺失摘要字段、表格或表格行时，必须补齐后再输出。
- 企业盈利预测部分只要输出未来预测或三情景预测，就必须包含 `预测口径` 和 `研报依据` 两个信息块；缺少 `研报依据` 表或表头不是 `日期 / 研报标题 / 发布机构 / 用途` 时，必须补齐后再输出。
- 若完整报告缺少任一维度模板字段、表格、综合评级依据或硬评分计分式，必须补齐后再输出。
- 第八部分只做综合收束，不得替代、压缩或改写前六个维度。

### 单维度输出验收

- 单独调用某一维度时，输出颗粒度不得低于完整报告中对应维度的完整模板。
- 单独调用行业生命周期时，必须输出 `02` 的完整四段结构、字段式结论摘要和增长阶段特征表；不得追加行业景气度、企业盈利预测、PEG 或成长股特征结论。
- 单独调用行业景气度时，必须输出关键依据表和评分口径说明表；股票模式为 5 分制，行业直问为 4 分制。
- 单独调用 PEG 时，必须输出三情景 PEG 表；单独调用成长股特征时，单股模式必须输出 10 项特征表。

### 轻量可读版验收

- 默认单股输出必须采用总分总结构，不得默认输出七段式完整报告。
- 必须包含：先说结论、核心判断表、三个核心理由、两个主要风险、反证信号、成长大师式总结、下一步可以继续了解。
- 核心判断表必须包含固定维度：生意可理解度、成长大师分类、成长线索、行业阶段、行业景气趋势、盈利增长质量、PEG成长观察、成长股特征匹配、框架适配度、最大风险。
- 核心判断表的“判断”必须使用 `references/07-综合输出与表达规范.md` 定义的固定枚举。
- 每个关键判断必须有依据；暂无法判断时必须显式写“暂无法判断”“待后续数据复核”或“当前公开证据尚不足以支持强判断”。
- 下一步引导必须输出 3-4 项，且至少包含“查看完整分析”；其余推荐项必须与本次分析结论相关，不得诱导交易。
- 暂无法判断、框架适配度低、风险显著高于优势、估值无法判断时，必须按 `references/data-gap-policy.md` 的轻量版兜底规则降置信度。
- 不得出现买入、卖出、持有、加仓、减仓、满仓、清仓、止盈、止损、目标价、上涨空间、抄底等交易化文案，免责声明中的否定性列举除外。

## 验证

- 不要求运行自动化测试。
- 人工检查主 `SKILL.md` 是否只引用新 references 和 `$skill-name`。
- 人工检查五个 reference 是否承接成长大师业务框架，并符合当前三层调用链路。
- 人工检查主包未引用历史本地薄包装路径，`skills/` 下只保留可独立复用的原子能力。
- 修改触发行为、路由、依赖、数据访问或用户可见输出时，必须同步更新 `CHANGELOG.md`。
